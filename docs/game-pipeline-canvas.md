# 游戏制作管线需求：首期策划 → 美术

> 更新：2026-11-02；状态：首期核心功能已接入，真实生成与完整浏览器验收待完成。本文替代旧版 P0—P4 方案。
> 开发顺序见 [开发流程](game-pipeline-development.md)。

## 1. 产品目标与范围

最终目标是策划 → 美术 → 代码 → 测试 → 交付的完整游戏制作工具。现有美术画布是起点，不是产品边界。

首期交付：**想法或文档 → 策划草案 → 用户确认 → 资产拆解 → 美术方向确认 → 生成节点 → 候选选用 → 规格检查 → 资产包导出。**

首期完成不是“节点创建成功”，而是必需资产具有明确用途、规格、已选真实文件、检查记录和可导出路径。

支持范围：

- 文字想法、手写策划、UTF-8 Markdown/TXT 导入，单文件最大 1 MiB（1,048,576 字节）。
- AI 辅助策划与资产拆解，所有环节允许人工修改。
- 2D 静态角色设定、头像、场景背景、物件和 UI 图标；区分概念图与运行时素材。
- 单项目绑定一张现有画布，项目可含多个文档；复用现有生成通道。
- 保存恢复、局部更新、单项失败重试、候选选择、规格检查与导出。

### 策划工作台增补（2026-11-02）

- 文档节点提供展开编辑和安全 Markdown 预览（标题、粗体、斜体、列表、代码块、引用、链接及图片；不是完整 CommonMark 渲染器），可插入连接的本地图片并导出 `.md`。
- 文档和表格的 AI 修改先生成独立候选，采用后才保存。手工草稿必须先保存；来源修订变化时，保存/采用需要明确确认。失败、截断、无效 JSON 不覆盖原文；已有候选保留。
- 画布右键“游戏项目 → 策划表格”创建表格节点；支持文本/数字/布尔列、行列增删、单元格编辑、列类型转换、矩形 TSV 粘贴及 UTF-8 CSV/TSV 导入、CSV 导出。CSV 导入按文本保留前导零。最多 100 列、1000 行、单元格 10000 字符、保存及导入 4 MiB；无公式计算。
- 表格以 `project.json` 内的 `tables` 为权威来源，删除节点保留数据，同项目复制节点引用同一表格。表格编辑器提供会话内最近 30 步撤销/重做；手工草稿与 AI 候选随画布保存。
- 图片节点可连接到策划、文档、表格节点；策划和 AI 编辑将最多 8 张本地 PNG/JPEG/WebP 转为图像内容发送给所选聊天模型，需使用支持视觉输入的模型。拒绝远程 URL、任意路径及跨账号私有文件。连线不会自动触发模型请求。
- 表格可连接到策划节点作为结构化需求；表格修改使已确认策划标记来源变化。ZIP 同时包含 `documents/<id>.md` 与 `tables/<id>.json`。
- 从节点输入端拖线到空白处可反向创建上游：策划支持灵感、文档、表格和图片，资产拆解支持策划，文档/表格支持图片。选择后创建并自动连接；文档/表格等待项目保存成功后才连线。普通生成器、LLM、Output 和循环节点也按当前连线规则筛选上游类型。
- 文档/表格每次更新保留最近 30 个旧版本，节点“历史版本 / 恢复”可预览并恢复；恢复创建新修订，旧的当前内容仍可恢复。历史存储于项目 `history/{documents|tables}/<id>/<revision>.json`，不打入交付 ZIP。
- 当前项目与既有 JSON 自动兼容：旧项目未包含 `tables` 时视为空表格列表。历史从本次升级后的首次修改开始记录，不补造过去版本。

本期不交付代码生成、游戏试玩、发布、多画板、跨项目共享文档、多 Agent、自主长时间执行。3D、音视频、动画帧表与引擎自动导入暂不纳入验收。这是分期范围，不是最终产品限制。

## 2. 用户流程与功能需求

### 2.1 项目与文档

- 在“新建画布”中选择独立的“游戏项目”类型，自动建立游戏项目与灵感 → AI 策划 → 资产拆解节点及连线；普通画布不显示游戏项目入口。旧版已关联项目保留兼容；一画布最多关联一个项目。
- 主流程在画布节点中完成：一句话输入、生成与采用策划、拆解与采用资产清单，再创建提示词及图片生成节点。项目面板负责管理、验收与导出。
- 文档节点直接编辑标题、正文并保存，显示版本；支持不用 AI 手写。灵感节点可添加需求文档节点并接入策划。
- 文档属于当前项目，不支持跨画布同步；导入文档作为内容，不作为系统指令。
- 删除节点不删除正文；同项目复制文档节点引用原正文，跨项目粘贴拒绝并提示。

### 2.2 策划生成与确认

- 复用现有 LLM 渠道与模型配置，不另建一套密钥管理。
- 策划包含玩家目标、核心循环、操作、进程、胜负与重开、首个可玩范围、美术方向、验收条目。
- 缺失信息列为待确认问题或明确标注的假设，不能伪装成用户已确认需求。
- AI 输出先进入候选，用户可编辑、采用或丢弃；结构校验通过不等于用户确认。
- 截断、空输出、失败不覆盖旧版。校验错误允许一次修正重试，仍失败保留候选与诊断。
- 候选记录来源文档 hash 和项目 revision；来源已变化时禁止无提示采用。

### 2.3 资产清单与美术方向

- 从已确认策划生成清单候选，支持手工增删改；AI 修改清单时展示新增、修改、移除差异，由用户采用。
- 每项有稳定 ID、名称、用途、概念/运行时分类、是否必需、规格、提示词、参考图和导出目标。
- 角色与场景引用 asset ID；只从 assets 清单创建生成节点，不重复遍历角色和场景。
- 项目保存风格说明、配色和共享参考，单项允许覆盖；实际生成保存参数快照。
- 可以先生成代表性资产确认美术方向，再生成其余资源。角色后续图片可引用已选设定图。
- 共享参考有助于一致性，但最终外观与质量须人工检查，不能承诺模型自动保证一致。

### 2.4 节点与生成

- “创建节点”“实际生成”“选用结果”为独立动作，创建节点默认不扣费生成。
- 复用现有提示词、参考图、生成器、结果节点及其真实输入字段。
- image 是媒体承载节点，不是生成器。优先打通一个实际可用的 generator 或 msgen 通道，再扩展其他渠道。
- ComfyUI/RunningHub 仅在已配置、可验证的图片工作流下开放，不能仅按节点名称推断能力。
- projectId + assetId 唯一定位绑定，重复创建不产生第二套；节点移动不影响关系。
- 删除绑定节点保留资产和文件，提示绑定缺失，允许用户重新创建。
- 批量执行前显示数量、渠道及已有可靠报价；不能获得报价时不虚构费用。
- 沿用现有并发与取消能力，单项失败独立重试；停止等待不等于上游任务取消，不自动反复付费重跑。

### 2.5 候选、选用与检查

- 一项可以有多个候选，用户显式选择；重生成不自动替换已选版本。
- 候选关联资产、来源节点、输出标识、生成参数和资产修订号；旧任务晚到不得覆盖新选择。
- 选用时验证当前用户对源文件的访问权限，将真实文件复制到项目版本目录，原文件保留。
- 自动检查实际格式、尺寸、可读性与 alpha 信息；“有 alpha 通道”不能等同于“背景已透明”。
- 语义、裁切、风格一致性和真实透明效果由人工确认；规格不符时标记待处理。
- 可复用现有修图能力或上传修正版，本期不承诺自动去底、切帧、动画生成。
- 候选源文件缺失要显示诊断；已复制的选用文件不依赖源文件继续存在。

### 2.6 导出与完成

- ZIP 包含选用资源、manifest.json、策划快照与检查摘要，不含密钥、聊天历史及内部绝对路径。
- 概念图放 references/，不能抵充必需运行时资产。
- 必需资产缺失、待更新、未检查或规格失败时，不允许正式完成；允许用户显式导出带未完成清单的草稿包。
- 清单记录 projectId、策划及资产版本、相对目标路径、格式、尺寸和内容 hash。
- 下载接口检查 owner；导出对应确定的项目 revision，不能边导出边混入新版本。

## 3. 数据与存储契约

### 3.1 项目落盘

保留 canvases/<canvasId>.json，首期不拆分现有画布存储。

```text
USER_DATA_DIR/game-projects/<projectId>/
  project.json
  documents/<docId>.md
  assets/<assetId>/<selectionId>.<ext>
  exports/
```

- project.json 是项目元信息、文档索引、策划、资产与绑定的权威来源，包含 schemaVersion、owner、canvasId 和 revision。
- 画布节点只持 projectId、docId 或 assetId 等定位信息，不复制完整策划和正文。
- 新增项目数据不能假定 CanvasSaveRequest 会自动保存，项目通过独立接口保存。
- 项目级 revision 乐观并发控制，冲突返回 409，保留本地草稿并允许选择版本；不只依赖 mtime。
- 文档索引保留正文 hash、版本与上次保存内容，用于检测正文和索引写入中断；不一致时明确恢复，不能默默采用混合版本。
- 文件先临时写入并校验，最后原子提交元数据引用；多文件不具备整体事务时必须检测中断并可恢复。
- 项目与画布绑定采用稳定关联标识，重试核对并补齐，不因中断产生重复节点。
- 项目首期采用归档与解除关联，不自动物理删除文件；未引用文件也不自动清理。

### 3.2 策划结构

| 字段 | 内容 |
|---|---|
| schemaVersion | 固定 1，与内容修订号分离 |
| revision | 策划修订号 |
| title / playerFantasy | 游戏名称、玩家目标和体验 |
| coreLoop / controls | 核心循环和主要操作 |
| progression / successFailureRestart | 进程、成功失败及重开 |
| firstPlayable | 首个可玩范围与排除项 |
| visualDirection | 风格、配色、共享参考 |
| characters / scenes | 稳定 ID、描述及引用的 assetIds |
| openQuestions / assumptions | 待确认问题与假设 |
| acceptanceCriteria | 后续实现与测试可复用的验收条目 |

可执行契约见 core/game_project_models.py，接口请求模型见 routers/game_projects.py；示例 JSON 不替代模型校验。项目最多 100 文档、200 资产；图片每边不超过 8192，单项有效参考图最多 20。渠道能力仍须实际核验。

### 3.3 资产条目示例

```json
{
  "id": "asset_hero_portrait",
  "revision": 1,
  "name": "主角头像",
  "purpose": "游戏 HUD 头像",
  "usage": "runtime",
  "required": true,
  "kind": "image",
  "spec": {"width": 256, "height": 256, "format": "png", "alphaRequired": true},
  "prompt": "主角正面头像，完整保留头部轮廓",
  "referenceAssetIds": [],
  "runtimeDestination": "assets/characters/hero_portrait.png",
  "generatorNodeId": null,
  "selected": null,
  "review": {"status": "pending", "issues": []},
  "needsUpdate": false
}
```

- usage 为 concept 或 runtime，本期 kind 只接受 image。
- selected 记录 selectionId、relativePath、sourceNodeId、sourceOutputId、contentHash、sourceAssetRevision。
- 任务状态、检查状态、needsUpdate 分开存储；已选资源不是“生成成功”的同义词。
- ID 不从名称生成，重命名不改变 ID；生成快照记录实际参数但不存密钥。
- 后端检查 ID 唯一、引用存在、循环参考、规格上限、扩展名匹配，拒绝未知字段。
- 导出路径按 Windows 大小写不敏感规则判重；拒绝绝对路径、盘符、反斜杠绕过、..、保留名称和目录逃逸，解析后再次检查根目录边界。

## 4. 变化与失败处理

| 变化 | 行为 |
|---|---|
| 文档修改 | 策划标记来源已变化，不自动改写 |
| 采用新策划 | 展示清单差异，不自动生成 |
| 资产规格/提示词/参考变化 | 增加资产修订号，标记待更新，保留旧选用 |
| 共享风格变化 | 标记引用该风格的资产，单项覆盖规则明确 |
| 用户认定旧图仍适用 | 显式重新确认，记录适用修订与检查结果 |
| 移除资产 | 先排除，保留文件；被引用时提示并阻止直接移除 |
| 重生成失败/旧任务晚到 | 保留已选版本，结果只作为候选 |
| 通道不可用/文件缺失 | 具体诊断，不影响无关资产 |
| 保存冲突 | 保留草稿，提供版本选择 |

新接口必须继承现有身份和 owner 校验，随机 ID 不代替权限。模型文本安全渲染；不能根据模型路径任意读取本机文件或下载任意 URL。跨项目引用拒绝。刷新后恢复已保存结果，未保存内容提供草稿恢复或明确离开提示。

## 5. 首期验收

样例：俯视角探索游戏，五项资产——角色概念图、角色头像、背景、两个图标；后四项为必需运行时资源。

1. 想法/导入文档可生成并编辑策划，未经确认不自动生成美术。
2. 五项用途与规格明确，重复创建节点不重复绑定。
3. 风格和角色参考可复用；创建、生成、选用分开操作。
4. 候选可选用并检查真实文件，概念图不能替代运行时资源。
5. 重生成失败和旧任务回调不覆盖当前选择。
6. 修改头像规格只标记该项及明确依赖项，不重做无关资产。
7. 关闭重开后正文、策划、绑定和已选版本一致，失效绑定可恢复。
8. 正式包解压后所有 manifest 路径存在且 hash 匹配；缺必需项只能导出草稿。
9. 越权、路径逃逸与跨项目引用被拒绝。

模拟渠道可用于开发测试，但没有真实生成链路验收时必须标注未验证，不能宣称完整通过。

## 6. 后续全流程演进

### 源码对照补充：首期必须遵守

依据 [OhMyGame 源码经验](ohmygame-source-lessons.md)，以下作为首期验收补充：

- 生成前等待关联文档、策划与参数保存；保存冲突时不得发起生成。
- 分开复用结果、跟随运行中任务与显式再生成；以解析后的输入及参考内容版本计算请求指纹。
- 跟随者停止等待不取消别人启动的任务；重启后先查询已有任务，不自动重复付费。
- 保存、刷新与冲突选择串行；恢复版本后使用新 workspaceEpoch，使迟到保存和旧回调失效。
- 最新生成结果只进入候选，不自动替换 selection；缺失无关候选不阻止项目打开。
- 首条链路允许 revision 冲突人工选择，不要求提前实现完整三方合并。

后续需求见 [游戏工程、数据、测试与交付需求](game-production-requirements.md)，阶段 G—N 见 [后续开发流程](game-production-development.md)。

首期通过后复用同一项目、策划验收条目、资产 ID 和 manifest，接入普通游戏工程、执行 Agent、运行与实际操作测试，再形成修复闭环。

不预建多 Agent、引擎插件框架、多画板。单 HTML 可以作为后续原型模板，不作为最终工程限制。OhMyGame 参考：[画布协议](https://github.com/WhiteTowerAI/ohmygame/blob/c30bfabda86c27084128deca5bc4bd0d4e9983eb/docs/canvas-agent.md)、[Game Studio](https://github.com/WhiteTowerAI/ohmygame/blob/c30bfabda86c27084128deca5bc4bd0d4e9983eb/plugins/game-studio/skills/game-studio/SKILL.md)。

### 拆解结果创建图片节点

资产拆解节点展示每项 AI 生成提示词；勾选需要的资产，点击“创建所选图片生成节点”。候选清单会先整体采用，再仅为选中项创建或更新提示词与图片生成器节点，并自动连线、带入尺寸和美术风格。创建节点不会自动调用图片接口；在生成节点中运行即可生成美术效果图。
