## 1. 执行摘要

本文档为 Art Canvas 项目 P2 架构重构的实施路线图。基于 P0/P1 治理成果（详见 `docs/architecture.md`），规划了 4 个阶段的渐进式迁移路径，预计总周期 **10-15 周**。

**核心决策**：
- 后端：按领域拆分 main.py → routers/
- 前端：Vue 3 渐进式迁移（试点先行）
- 测试：先补单元测试，再做大重构
- 数据：SQLite 迁移（阶段 4）

## 3. 阶段详情

### 阶段 1：后端路由拆分（Week 1-4）

**目标**：将 main.py 从 16,000 行拆分为 8-10 个 router 文件 + 启动入口。

#### Week 1-2：基础架构

| Day | 任务 | 交付物 |
|---|---|---|
| 1-2 | 创建 `routers/` 目录结构 | 8 个空 router 文件 |
| 3-4 | 提取共享依赖（services/）| services/auth.py, services/canvas.py |
| 5-7 | 拆分认证路由 | routers/auth.py（已完成 ~800 行）|
| 8-10 | 拆分画布路由 | routers/canvases.py（已完成 ~1500 行）|
| 11-14 | 拆分 ComfyUI 路由 | routers/comfyui.py（已完成 ~1000 行）|

**验收标准**：
- [ ] main.py 减少 5,000 行
- [ ] 所有认证/画布/ComfyUI 路由通过冒烟测试
- [ ] git diff 审查通过

#### Week 3-4：剩余路由与集成

| Day | 任务 | 交付物 |
|---|---|---|
| 15-18 | 拆分即梦/RunningHub 路由 | routers/jimeng.py, routers/runninghub.py |
| 19-22 | 拆分 TTS/工作流/资产路由 | routers/tts.py, routers/workflows.py, routers/assets.py |
| 23-25 | 清理 main.py 残留 | main.py < 5,000 行 |
| 26-28 | 集成测试 | 全量路由可用 |

**验收标准**：
- [ ] main.py < 5,000 行
- [ ] 250+ 路由全部可用
- [ ] 零回归 bug

**风险点**：
- 全局状态分散：需用 services/ 统一管理
- 循环导入：需 careful refactoring
