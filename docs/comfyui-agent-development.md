# 画布 AI 节点开发与桌面插件架构：含 ComfyUI 工作流

更新：2026-11-04。状态：分阶段开发中，独立依赖环境见第 23 节，静态图片能力见第 22 节，其他已落地能力见第 21 节；第 19—20 节保留阶段历史，其余章节为目标设计，不代表全部功能或测试已经完成。

架构定位：本方案面向通用画布节点开发，ComfyUI 是首个重点实现的执行适配，不是所有节点的基础或必需依赖。第 1—14 节描述 ComfyUI 专项闭环，第 15 节描述桌面插件机制，第 16 节规定各种节点共同遵循的宿主协议。

## 1. 目标与交付体验

用户在画布 AI 对话中描述任务，AI 自动规划、生成复杂 ComfyUI 工作流，发现并安装缺失插件，准备模型，执行测试，根据真实错误有限修复，最终将通过测试的工作流配置成一个可复用的画布节点。

示例需求：“创建商品图工作流，支持上传商品、去背景、保持主体、替换背景、局部重绘和最终放大，做好测试后放到画布。”

交付物包括：ComfyUI API 工作流、用户参数面板、输入输出映射、依赖清单、版本锁定记录、测试输入及结果、一个已配置的画布 ComfyUI 节点。复杂内部图封装在一个画布节点中，用户可查看内部工作流和测试报告。

默认执行已授权范围内的安装、测试和交付，不为每一步重复确认。聊天显示阶段、关键日志和结果预览；只有缺少必要输入、超出既有权限或资源预算时才请求用户决定。

## 2. 现有基础及缺口

| 能力 | 已核对的代码 | 本次复用与补充 |
| --- | --- | --- |
| AI 工具循环与候选方案 | `core/canvas_agent.py` | 复用工具调用；补充 ComfyUI 构建工具及结构化交付 |
| 画布候选采用 | `static/js/canvas-agent.js` | 前后端同时支持 `comfy`，采用时校验候选版本 |
| ComfyUI 节点 | `static/js/canvas.js` | 复用 `comfyWorkflow`、`comfyParams` 和自定义模式 |
| 工作流存储 | `routers/workflows_legacy.py`、`routers/workflows.py` | 复用自定义工作流及配置格式；增加完整校验和不可变版本 |
| ComfyUI 查询与执行 | `routers/comfyui.py` | 复用 object_info、prompt、history、queue、上传和进程管理 |
| 画布异步执行 | `routers/canvas_comfy.py` | 复用生成执行；构建任务另设持久化生命周期 |
| 工具授权 | `core/mcp_tools.py`、`routers/mcp_tools.py` | 沿用本地主机会话与已有授权语义，不把 MCP 服务信任等同于所有系统权限 |

当前 AI 候选不允许 `comfy` 类型或结构化参数；工作流创建接口只检查首个节点是否有 `class_type`，不足以保证可执行；未发现可直接复用的完整插件安装与自动验证闭环。

普通聊天工具循环目前有轮次限制，不应简单放大限制来承载长时间安装和推理。工具启动持久化构建任务，再查询进度和提交交付候选。

## 3. 范围与边界

必须实现：基于模板修改、从零组合复杂图、安装已有第三方自定义节点插件、模型依赖发现、真实推理验证、有限自动修复、画布交付与再次运行。

“复杂节点”默认指封装复杂工作流的画布节点；“安装插件”指安装现有 ComfyUI 自定义节点包。AI 编写全新 Python 插件作为后续独立阶段，不与首版安装能力混为一谈。该阶段仍属于最终扩展范围，但需要代码候选、独立环境测试与发布管理。

本地受管 ComfyUI 支持自动安装与受控重启。只有 HTTP 地址的远程 ComfyUI 支持能力查询、生成、测试；自动安装需要远端受认证的执行代理，普通 ComfyUI HTTP API 不提供通用远程系统安装能力。不使用本机路径去修改远端环境。

模型下载按已有授权、磁盘空间和下载预算执行；付费、登录、许可证确认、无法访问的资源进入等待状态，不伪造下载完成。

## 4. 完整流程

1. **理解任务**：整理输入、输出、处理步骤、画质、耗时、显存预算及验收条件；只有影响方向的缺项才提问。
2. **探测环境**：锁定目标实例，读取健康状态、object_info、模型枚举、GPU、Python 环境、插件及版本。
3. **制定方案**：优先复用项目工作流和模板；根据真实节点定义生成操作图、依赖计划和参数映射。
4. **准备依赖**：安装缺失插件和允许下载的模型；必要时等待队列空闲并重启；刷新能力快照。
5. **生成候选**：生成 API 图和配置，执行结构、类型、输入输出与资源检查。
6. **运行测试**：上传测试素材，提交真实推理，收集节点错误、日志、耗时和输出。
7. **有限修复**：根据证据定位问题，形成新版本，重新执行受影响检查；环境没有变化时不反复安装。
8. **发布交付**：测试通过后原子发布，生成画布节点候选；按已授权的自动交付设置直接采用，否则使用现有“采用方案”。
9. **再次运行**：从画布改参数、连入图片或文本并执行，结果沿用现有输出机制。

每次构建固定实例 ID、环境指纹和候选哈希。安装或重启后指纹变化，必须重新验证；测试期间不得静默切换到另一实例。

## 5. 最小模块设计

建议新增以下模块，名称为规划，不表示已经存在：

| 模块 | 职责 |
| --- | --- |
| `core/comfy_build_tasks.py` | 状态、持久化、取消、恢复、事件及阶段调度 |
| `core/comfy_environment.py` | 实例探测、插件与模型解析、安装、环境锁和重启 |
| `core/comfy_workflow_builder.py` | 图生成、校验、参数映射及版本发布 |
| `core/comfy_workflow_tests.py` | 测试提交、输出检查、报告与修复证据 |
| `routers/comfy_builds.py` | 构建任务、事件、候选及发布接口 |

以现有 Python、HTTP 客户端、子进程和文件持久化能力实现，不新增通用 Agent 框架、工作流引擎、消息队列或数据库依赖。项目已有合适持久化组件时直接复用。先实现单主机受管执行，多机器调度不进入首版。

## 6. AI 工具与接口契约

AI 仅调用限定操作，不获得任意 shell 工具：

| 工具 | 核心参数 | 返回 |
| --- | --- | --- |
| `comfy_inspect_environment` | instance_id、节点类型筛选 | 能力快照、环境指纹 |
| `comfy_start_build` | canvas_id、instance_id、需求、输入引用、预算 | build_id |
| `comfy_get_build` | build_id、事件游标 | 阶段、进度、阻碍、结果 |
| `comfy_cancel_build` | build_id | 取消状态及未完成清理 |
| `comfy_propose_node` | build_id、revision | 引用已验证产物的画布候选 |

建议 HTTP 接口：`POST /api/comfy-builds`、`GET /api/comfy-builds/{id}`、`GET /api/comfy-builds/{id}/events?after=...`、`POST /api/comfy-builds/{id}/cancel`、`POST /api/comfy-builds/{id}/publish`。事件通过 SSE 或现有流式通道发送，轮询仅作降级。

所有接口校验用户、画布访问权和任务归属；环境修改仅允许主机授权执行上下文。状态变更请求携带幂等键，发布携带候选 revision 和哈希。刷新、重试或重复工具调用不能重复安装或创建多个节点。

AI 不直接提交路径、安装命令和任意节点字段。服务端由 build_id 解析已验证工作流与参数；画布候选只携带服务端生成的 artifact_id/revision 引用，解决现有字段仅支持短字符串的问题。

## 7. 数据与状态

任务记录至少包含：id、owner、canvas_id、instance_id、需求、输入引用、状态、stage、revision、environment_fingerprint、budget、依赖计划、安装记录、测试记录、artifact_id、错误、事件游标、创建及更新时间。

状态为 `queued → running → succeeded / failed / cancelled`；需要用户输入或授权时进入 `waiting_input`。stage 表示 inspect、plan、install、generate、validate、test、repair、publish。界面区分“工作流已测试”和“画布已采用”，不把方案生成成功显示成全部完成。

任务与事件存储于应用用户数据目录，采用原子写入；大日志、图片和模型不塞进任务 JSON 或模型上下文。服务重启后将未完成本地子进程标为待核对；已有 prompt_id 先查询历史，无法确认时报告中断，不盲目重复执行。

产物目录包含 `workflow.api.json`、`config.json`、`manifest.json`、`tests/report.json` 和输入输出引用。manifest 记录插件仓库及 commit、包版本、模型标识、测试时环境指纹、工作流哈希。可选保存 ComfyUI UI 格式文件，但 API 格式为执行依据；UI 格式转换需单独验证，不能假设与 API 格式相同。

## 8. 插件安装与环境管理

### 8.1 依赖发现

按 `class_type → 插件标识 → 仓库/版本` 解析，优先已验证映射及项目模板。ComfyUI Registry/Manager 只作为可选适配，先探测版本和实际能力；不能假定任意安装版本具有同一套接口。

节点名称不能可靠唯一定位插件。存在歧义时根据来源、版本、维护情况和兼容信息选择；无法确定时保留阻碍，不让模型猜仓库 URL 后直接安装。

### 8.2 安装流程

解析受管 ComfyUI 根目录、实际运行 Python 和启动方式 → 获取实例级环境锁 → 保存插件与包清单 → 在临时目录拉取固定版本 → 校验清单与目标路径 → 使用该实例 Python 安装依赖 → 移入 custom_nodes → 等待队列空闲 → 受控重启 → 检查启动日志及 object_info 中目标节点是否注册 → 记录版本。

子进程使用可执行程序加参数数组，不拼接 shell 字符串；安装路径限制在受管实例；URL、重定向与下载路径按资源类型校验。插件安装脚本与 pip 包均会执行第三方代码，可信来源安装也需要在已授权的环境范围内运行。

同一实例不允许并行安装。已有任务运行时不强制杀进程；外部启动且不受管的实例只能提示手动重启或通过已配置代理重启。取消请求需要终止本任务管理的进程树、清理未完成目录，不影响其他实例。

### 8.3 冲突与回退

优先保留现有 torch、CUDA、Python 和已运行工作流依赖；检测到需要升级基础环境时生成迁移方案，超出当前授权则暂停。不得自动升级全部插件或执行无关修复。

新增插件失败可禁用或移走本次新增目录；升级已有插件需保留旧版本。`pip freeze` 只是清单，不是完整回滚：共享环境包变更无法保证原样恢复。高影响依赖变更在独立受管环境验证，通过后切换；无可用快照时必须明确部分回退状态。

## 9. 工作流生成与画布参数

从能力快照按需取节点定义，避免把整个 object_info 塞给模型。支持多阶段处理、分支、多个模型、蒙版、ControlNet、LoRA、采样及放大组合；实际可用能力以目标环境为准。

图校验至少覆盖：所有节点的 class_type、必填输入、枚举、数值范围、连接源及输出索引、类型兼容、悬空引用、有效输出及通向输出的依赖关系。普通数据图检测环；需要循环插件时按该插件真实契约适配，不假定任意循环都可执行。动态输入与自定义校验不能完全靠 object_info 推断，以后端实际提交验证为准。

参数配置沿用现有 config 字段格式，实现前逐项核对 renderComfyCustomField 和 runComfyNode 的消费方式。概念映射为：界面字段 ID → API 节点 ID → input 名称；支持文本、整数、小数、枚举、布尔、图片、蒙版、seed。需要新增控件时同时补渲染、序列化与执行逻辑。

交付节点使用 `type: comfy`、自定义模式、已发布 `comfyWorkflow` 和经过字段校验的 `comfyParams`。输入连线按明确映射进入图；不同语义的多张图不能只依赖连线顺序。输出声明主图、蒙版或其他媒体角色；首版可先交付图片输出，视频和音频必须分别实现检查器再宣称支持。

已有节点绑定发布版本；重新生成产生新版本，通过测试后再替换绑定，失败不覆盖可运行版本。保存工作流、配置、报告及采用节点需处理部分失败；用发布清单作为提交标记，未完成产物不出现在可用列表。

## 10. 自动测试与修复

### 10.1 测试层级

| 层级 | 检查内容 | 通过标准 |
| --- | --- | --- |
| 静态校验 | 图结构、参数映射、节点/模型存在性 | 无未解决错误 |
| 小规模冒烟 | 合理降低尺寸或步数，真实提交 | history 无执行错误，声明输出存在并可解码 |
| 目标配置测试 | 用户约定尺寸、步骤及输入 | 完整链路执行成功，产物符合技术规格 |
| 画布集成 | 采用、保存恢复、连线输入、改参重跑 | 使用发布版本成功执行，输入输出映射正确 |
| 质量验收 | 与任务有关的主体、蒙版、背景、细节 | 明确指标通过，或标记需人工确认 |

冒烟成功不等于目标配置成功。固定 seed 与测试素材用于定位回归；GPU 推理允许数值差异，不要求输出字节完全一致。结果检查包括空文件、解码失败、尺寸、通道、数量、明显异常图；视觉模型评分仅为辅助证据，不能把“文件存在”说成语义质量达标。

每条代表性处理分支都需被测试输入覆盖；随机分支未执行、条件未满足时记录未覆盖。没有用户素材时使用有来源记录的测试素材，明确真实用户素材尚未验证。正式目标配置因显存或预算不能执行时，不标为完全验证。

### 10.2 修复规则与预算

收集 prompt_id、失败节点、错误码、堆栈摘要和前后版本差异，再分类处理：缺插件、模型不存在、类型/尺寸不匹配、显存不足、版本冲突、下载失败或质量不达标。

默认最多 3 次修复，每次必须有新证据和明确修改假设；第三次仍失败即结束并交付阻碍。网络错误仅有限重试；依赖冲突不得通过无限升级解决。显存不足允许在既定目标范围内优化；降低用户要求须明确记录并取得需求调整，不能静默降级后判成功。

可配置预算包括总时长、单次执行时长、安装时长、测试次数、下载字节和磁盘占用。超时先检查任务和队列，不重复提交；取消只删除自己的排队任务。全局 interrupt 可能影响其他运行任务，仅在确认当前执行归属或独占实例时使用。

## 11. 界面和交付

AI 侧栏显示“检查环境 / 安装依赖 / 构建 / 测试 / 修复 / 已完成”，安装项显示插件名称、版本和状态；测试项显示耗时、产物预览、通过项及未验证项。原始日志可展开查看。

提供停止、补充输入、查看报告、采用节点和打开工作流。收起侧栏不停止任务，刷新后从服务端恢复。环境已改变、候选过期或目标节点已删除时重新校验，不强行采用旧候选。

撤销画布节点只撤销画布操作，不隐式卸载插件或删除模型；界面说明环境改动仍保留。卸载是独立操作，应检查其他工作流引用。

## 12. 开发顺序与阶段验收

| 阶段 | 开发范围 | 必须验收 |
| --- | --- | --- |
| P1：打通闭环 | 已有插件/模型、持久化构建、工作流生成、真实测试、画布交付 | 一句话生成复杂模板变体，测试后成为可运行节点，刷新可恢复 |
| P2：自动补依赖 | 本地插件安装、模型资源计划、锁、重启、失败恢复 | 缺插件自动安装并注册；冲突不破坏旧环境；拒绝/取消可停止 |
| P3：复杂图与修复 | 多分支、多图/蒙版、目标配置测试、证据驱动修复 | 至少三类复杂工作流完整运行；失败不覆盖旧版本 |
| P4：完整产品化 | 远端代理、多媒体输出适配、报告和版本管理 | 断线恢复、重复请求幂等、跨实例隔离、支持媒体均有真实报告 |
| P5：新插件开发 | Python 插件代码候选、隔离测试、注册及版本发布 | 新节点接口与图兼容；隔离环境通过测试后才进入目标环境 |

P1 是基础里程碑，不能据此声称“自动安装与复杂工作流”全部完成；原始工作流目标至少包含 P1—P3。P4 按实际部署需求实施，P5 是从安装已有插件扩展到创造 ComfyUI 插件。后续补充的桌面端节点扩展需求还必须完成第 15 节的 D1—D3，不能以 P5 替代桌面节点插件机制。

## 13. 开发测试清单

建议新增后端测试 `tests/test_comfy_builds.py`、`tests/test_comfy_environment.py`、`tests/test_comfy_workflow_validation.py`，前端测试 `tests/test_canvas_comfy_delivery.cjs`；按实现拆分，不为了目录形式制造空测试。

- 单元测试：图类型与映射错误、依赖歧义、路径限制、版本指纹、状态机、修复预算和发布幂等。
- 协议集成：用可控 ComfyUI 响应模拟安装后注册、提交拒绝、执行失败、取消和恢复；明确模拟通过不代表真实推理通过。
- 真实环境：记录 ComfyUI、Python、GPU、插件和模型版本；至少覆盖已有环境、缺插件、插件导入失败、模型缺失、显存不足及服务重启。
- 画布验收：采用后保存恢复、输入连线、参数修改、输出展示、重复采用和旧版本回退。
- 隔离与权限：跨画布越权、非主机安装、路径穿越、并发安装、重启遇到其他任务、误中断他人任务。

真实复杂案例至少包括：商品去背景与重绘放大；参考图加蒙版/控制条件；多阶段采样与分支输出。测试报告记录每个案例的实际版本、输入、目标配置、耗时、输出和未覆盖范围。

## 14. 完成定义

用户从画布对话发起任务后，在授权和资源范围内无需手工编辑 JSON、手动配置参数或逐个安装插件。系统完成依赖准备、复杂图生成、真实目标测试，交付一个能接收输入、修改参数并重新运行的画布节点。

每次“完成”必须可追溯到工作流版本、环境指纹和真实测试报告。失败必须可定位、可停止，不损坏旧工作流，不伪报安装、测试或质量验收成功。

桌面正式安装包还应允许 AI 在没有项目源码、不修改内置后端的条件下创建、测试、安装节点插件；缺少适配 UI 时能开发组件或专用面板，并在重启后保留可用节点。具体完成条件见下节。

## 15. 桌面端节点插件与 AI 组件开发

### 15.1 补充需求与现状

软件编译发布后，用户不需要获得源码、修改内置后端或重新打包软件，就能通过 AI 增加节点功能。已有控件无法表达节点需求时，AI 可以开发新的参数组件、专用面板或独立执行插件，完成测试后安装到用户插件目录。

当前 `desktop/package.json` 使用 Tauri 2 构建桌面端，不能套用 Electron 的 Node 集成或动态 require 方案。下述条目是完整目标，已实现的 SDK、插件包、隔离 UI 和 worker 子集见第 21 节，不代表所有端口和运行时均已适配。

已有基础包括：节点外壳、连线、保存及撤销；`renderComfyCustomField` 的文本、数字、滑块、下拉与布尔控件；Seed 随机功能；生成参数面板的部分共享控件。它们尚未形成统一的 AI 可发现组件目录或通用节点 SDK，部分依赖页面 DOM、全局状态和固定节点类型。

首步将直接相关控件接入明确的状态读写与事件接口，按需抽取，避免一次性重写所有节点或建立庞大 UI 框架。

### 15.2 三层扩展及选择顺序

| 类型 | 适用需求 | 交付与运行方式 |
| --- | --- | --- |
| 配置型节点 | 现有控件足够，组合不同工作流 | 节点声明、参数和端口映射，由宿主渲染执行 |
| UI 扩展节点 | 曲线、颜色、时间轴、蒙版、多图排序等新交互 | 插件自带编译后的 HTML/JS/CSS，通过隔离视图接入 SDK |
| 独立执行插件 | 新算法、Python 处理、外部程序调用 | 宿主管理独立进程，通过版本化协议通信 |

优先配置组合，其次新增组件或专用面板；只有缺少执行能力时才新增 worker 或 ComfyUI 插件。同一个插件可组合三层能力。前端交互组件不负责自行安装系统依赖。

缺口判断分为：参数控件缺失、专用操作界面缺失、执行能力缺失、全新节点形态缺失。不同缺口分别生成组件、面板、执行器或节点定义，不将所有变化都升级成新节点类型。

### 15.3 宿主与 SDK 的职责

宿主必须预先提供以下稳定接口，插件只能通过接口访问能力：

- **发现与注册**：列出可用组件、参数类型、输入输出类型、执行器、SDK 版本和能力限制；校验并注册插件定义。
- **节点状态**：读取当前实例参数、提交可序列化参数变更、参与撤销及保存恢复；不同节点实例状态隔离。
- **输入输出**：按端口 ID 读取类型化输入和媒体引用，发布输出；大文件通过受限资源句柄传递，不通过任意绝对路径暴露。
- **执行任务**：提交/取消本节点任务、调用允许的 ComfyUI 能力、报告进度、错误和结果；复用宿主队列与身份校验。
- **交互生命周期**：挂载、更新、卸载、尺寸变化、面板开关；移除视图时释放监听器与资源。
- **扩展管理**：安装、启用、停用、升级、版本迁移、回退及查看测试报告。

参数定义包括稳定字段 ID、类型、默认值、范围、枚举、校验规则和可选条件显示。端口定义包括稳定 ID、方向、数据类型、必填及多值规则。宿主执行校验，不能只信任插件界面。

AI 通过工具读取组件目录和 SDK 文档，提交插件候选、启动测试、查询结果及安装。建议提供 `canvas_list_components`、`canvas_get_plugin_sdk`、`canvas_create_plugin_candidate`、`canvas_test_plugin`、`canvas_install_plugin`；安装仅接受已测试候选 ID 和哈希，不接受模型拼出的任意执行命令。

### 15.4 插件包与存储

建议插件包布局：

```text
product-image-node/
  manifest.json
  node.json
  ui/                 # 可选，已构建的界面资产
  worker/             # 可选，独立执行程序或 Python 源码
  workflows/          # 可选，ComfyUI API 图与配置
  tests/              # 测试定义及素材引用
```

manifest 至少包含插件 ID、版本、支持的宿主 API 范围、节点入口、UI/worker 入口、声明权限、运行时依赖、支持的操作系统和架构、文件哈希。node.json 声明参数、组件引用、端口和执行绑定，不允许嵌入任意可执行表达式。

插件安装到应用用户数据目录下的版本化目录，例如 `plugins/<plugin-id>/<version>/`，不写 Program Files 或内置资源。候选、测试与正式安装目录分离，原子切换活动版本。工作流、插件资源与用户状态分开保存，升级不覆盖用户输入。

包解压检查路径穿越、绝对路径、符号链接及大小上限；哈希用于完整性与候选一致性，不等于来源可信。安装仍遵循实际用户授权和权限范围。

### 15.5 无源码条件下开发与加载

AI 开发环境需要随软件提供或按需安装 SDK 文档、模板、验证器与构建工具。首版 UI 插件可使用原生 HTML/JS/CSS，避免要求最终用户安装完整前端工程；需要打包的插件在独立构建环境产出静态资产。

宿主不在主画布上下文执行插件任意 JS。采用独立来源的沙箱 iframe 或受限 WebView，使用校验来源、会话和请求 ID 的消息桥通信；默认不授予 Tauri 原生调用权限。实际隔离方式在 D1 做技术验证，确认自定义协议资源、CSP、来源判断及消息桥均可工作。

worker 通过 JSON-RPC 或等效的版本化消息协议与宿主通信，处理超时、取消、进程崩溃与日志。它不是可动态修改的内置后端。Python 扩展使用受管独立运行时和依赖目录；可以按需下载匹配平台的运行环境，不能依赖用户已经安装 Python。

独立进程本身不等于操作系统沙箱。必须明确文件、网络、子进程等权限如何约束；无法实现系统级隔离的执行模式只用于已授权可信插件，并准确呈现其权限，不宣称能够安全运行任意未知代码。

首版允许安装后重新加载插件视图或重启应用生效；后续再实现热加载。已编译安装包必须能够加载用户目录插件，不能仅在源码开发服务器中验证可用。

### 15.6 AI 发现缺失组件后的闭环

1. 查询当前组件、节点和执行能力，先尝试复用或组合。
2. 列出具体能力缺口，确定新增参数组件、专用面板、worker 或 ComfyUI 插件。
3. 基于 SDK 生成插件候选、参数定义、端口、权限和测试方案，不修改宿主源码。
4. 在测试宿主及独立运行环境完成静态检查、交互检查、状态恢复和真实执行。
5. 收集证据进行有限修复，沿用第 10 节预算，不无限改代码或重装依赖。
6. 测试通过后安装、注册并创建画布节点；已有授权覆盖时自动完成，否则只对新增权限请求决定。
7. 失败保留候选和报告，活动版本不变；缺少宿主能力时明确报告需要升级软件。

新增可复用组件在声明作用域中进入组件目录，AI 后续可发现其参数契约。专用组件默认只供所属插件使用，避免直接污染所有节点或覆盖内置组件 ID。

### 15.7 兼容、回退与能力上限

画布保存插件 ID、节点类型、插件版本、状态 schema 版本和参数。插件缺失或不兼容时显示可恢复占位节点，保留原始数据与连线，不能删除或转换成其他节点。

升级前验证 API 兼容和状态迁移；迁移在副本上执行，失败回退。运行中任务固定使用启动版本，不在执行中热替换 worker。停用/卸载前检查画布和任务引用；插件崩溃不得拖垮主画布。

Tauri 原生能力、新硬件访问或宿主未开放接口不可能通过任意 JS 自动获得。SDK 已开放能力范围内可免更新扩展；超出范围仍需发布宿主新版本。节点插件包与 ComfyUI custom_nodes 插件是不同扩展体系，分别管理版本和安装目标。

### 15.8 开发阶段与验收

| 阶段 | 开发范围 | 必须验收 |
| --- | --- | --- |
| D1：桌面宿主与协议 | 组件目录、节点声明、版本化 SDK、用户目录加载、隔离视图与消息桥验证 | 正式打包环境无源码可安装配置型节点；状态和连线可恢复 |
| D2：自定义 UI 与执行 | 新组件、专用面板、独立 worker、受管运行时和权限约束 | 安装原本不存在的 UI；独立算法真实执行；无全局 Python 仍可运行 |
| D3：AI 开发闭环 | 候选生成、测试、有限修复、安装、注册、升级回退 | 对话触发缺失组件开发，测试通过后节点出现在画布并可重跑 |

桌面验收至少覆盖：滑块等内置组件组合；从未内置的颜色/曲线组件；多图排序或蒙版专用面板；独立图像处理 worker；插件崩溃；错误权限请求；不兼容版本；升级迁移失败；应用重启；缺插件占位恢复。

最终测试必须在没有仓库源码、没有开发服务器、没有全局 Python/Node 的干净用户环境中运行已编译安装包，记录系统架构、宿主/SDK/插件版本及测试报告。不得把开发态成功等同于桌面发布态成功。

## 16. 通用节点架构：不限于 ComfyUI

### 16.1 需求与原则

后续节点可以通过本地计算、云端 API、独立程序、媒体工具、数据处理或多个步骤组合实现，不要求生成 ComfyUI 工作流。用户描述目标后，AI 根据已安装能力、运行成本和实际需求选择执行方式。

节点分为节点定义、交互界面和执行绑定三部分。UI 组件与执行器解耦：同一个滑块、上传控件或曲线面板可以服务不同执行方式；相同执行能力也可以绑定不同的参数界面。纯展示或交互节点可以没有执行器。

ComfyUI 专属字段、环境探测、插件安装和测试流程只存在于对应适配中。通用节点不继承 `comfyWorkflow`、`comfyParams` 或 ComfyUI 的输入输出假设。保留现有 ComfyUI 节点的数据兼容适配。

### 16.2 执行方式

| 方式 | 示例 | 运行与依赖 |
| --- | --- | --- |
| 宿主内置能力 | 文本转换、已有图像工具、资源查询 | 通过已注册的宿主操作调用，不注入宿主代码 |
| 插件界面内计算 | 颜色计算、曲线编辑、轻量数据变换 | 隔离视图或受控计算环境，限制耗时和数据量 |
| 独立 worker | Python 图像算法、FFmpeg、命令行工具 | 受管运行时、平台依赖与进程协议 |
| 外部 API | 云端生图、语音、翻译、业务服务 | 宿主代理请求、凭据引用、配额与费用记录 |
| ComfyUI | 采样、蒙版、模型组合及复杂推理图 | 目标实例、工作流和模型/插件依赖 |
| 组合任务 | API 生成 → 本地处理 → 结果整理 | 编排已注册操作，记录每步输入、状态和产物 |

首版只实现真实需要的执行适配，不预先为所有方式建设通用引擎。组合任务先支持明确的顺序和依赖图；动态循环、分布式调度等在存在真实需求时单独设计。

### 16.3 统一节点与执行契约

节点定义包含 `typeId`、版本、参数 schema、输入输出端口、UI 入口或组件声明，以及可选执行绑定。执行绑定按 kind 区分配置，分别校验，不能使用一个允许任意字段的大对象代替具体契约。

运行请求包括 run_id、节点与画布身份、固定的插件版本、参数快照、类型化输入、资源句柄、预算和凭据引用。结果包括状态、类型化输出、产物引用、错误及必要的用量信息。进度和日志通过独立事件发送，不能将大量媒体内容塞入事件。

执行器统一支持能力查询、启动、状态查询和取消语义；无法即时取消的外部 API 需要返回真实状态。恢复与重试能力由执行器明确声明，不能默认所有操作都能安全重试。对发消息、付费调用或写入外部系统等副作用操作保留幂等键和执行记录。

凭据由宿主管理，通过引用注入获授权操作，不写入节点配置、插件包、画布导出或 AI 上下文。外部 API 的调用权限不等同于任意域名网络访问权限。

### 16.4 AI 的选择与开发流程

AI 先查询节点、组件和执行能力目录，再选择：复用节点 → 组合已有组件及执行器 → 开发缺失 UI → 开发新的执行适配或独立插件。允许采用不同路线，不能默认每次任务都调用 ComfyUI。

测试随执行方式变化：API 节点检查响应、超时、错误和用量；算法节点检查输入输出及边界；交互节点检查操作与状态恢复；组合节点检查步骤映射、失败传播、取消和部分产物。执行完成、技术规格正确、用户目标达标仍是不同验收层级。

如果新能力能在既有插件协议内完成，AI 生成插件并测试安装；如果依赖宿主尚未开放的原生能力，则报告 SDK 缺口并要求宿主版本升级，不改写已安装软件内置后端。

### 16.5 现有节点渐进适配

保留现有节点数据和运行方式，新增薄适配层接入注册、参数、端口、执行和状态契约，不进行全量重写。ComfyUI 可作为首个样板，但通用接口命名与数据结构不得绑定其专属概念。

参数组件按需移除对固定 DOM、全局状态和单一页面的依赖，改为接收定义、当前值和变更回调；内部仍可复用现有渲染代码。画布 AI 的前后端固定类型名单逐步改为读取经宿主校验的注册能力，注册信息不能自动扩大执行权限。

至少再选择一个非 ComfyUI 节点验证通用协议，例如纯本地图像处理或外部 API 节点。验收必须包含：未配置、未安装或关闭 ComfyUI 时，该节点仍可创建、保存恢复、执行及输出结果。

旧画布兼容、撤销、参数读写和连线映射通过后，再按实际需要迁移其他节点；内置节点使用直接渲染、第三方 UI 使用隔离视图，两者共享数据契约，不强制共享同一渲染环境。

## 17. 共享组件兼容与第三方节点样式

### 17.1 已有节点保护

其他用户创建的节点不能因为宿主更新共享组件而无提示失效。组件契约包括参数结构、默认行为、事件、序列化、端口语义及布局约束，不能只把函数签名称为接口。

| 修改 | 兼容处理 |
| --- | --- |
| 修复内部实现、保持原契约 | 兼容更新，验证直接受影响行为 |
| 增加可选字段且保留旧行为 | 兼容扩展，旧数据使用明确的兼容默认值 |
| 删除字段、改变类型或事件 | 发布不兼容版本，提供迁移或保留旧实现 |
| 改变默认值、单位或输入输出含义 | 按行为变更处理，不能静默改变旧节点结果 |
| 改颜色、间距、字体或尺寸 | 按样式兼容规则检查，不能直接认定无影响 |

节点和插件声明组件依赖，创建或发布时解析并记录实际组件版本、状态 schema 及布局契约版本。重复打开画布不得无条件解析到最新组件。不兼容组件版本可以并存，兼容修复是否更新由明确的版本策略控制并记录。

版本号必须对应真实保留的实现或兼容适配；不能记录旧版却始终调用同一份最新代码。兼容维护期限和替代方案需明确，无法加载时显示占位并保留原始参数、资源引用及连线。版本锁定不意味着必须继续执行存在已知严重问题的版本，可以停用并说明原因。

升级在状态副本上迁移和测试，通过后切换；失败保留旧状态及版本。导出记录可移植依赖清单，导入检查组件是否存在、版本是否兼容；不随画布导出密钥或隐式执行安装代码。

### 17.2 三类样式及影响范围

| 样式层 | 管理方式 | 影响范围 |
| --- | --- | --- |
| 全局主题 | 宿主提供颜色、字体、圆角等语义变量 | 主动采用主题的节点随主题变化 |
| 共享组件样式 | 随组件实现和布局契约维护 | 使用对应版本组件的节点 |
| 第三方专用 UI | 插件自带样式，在隔离视图内渲染 | 所属插件视图，不修改主画布或其他插件 |

主题变化与组件版本锁定分开：锁定组件的行为及布局契约，不承诺视觉像素完全不变。采用主题的旧节点仍可改变颜色和字体；需要固定品牌外观的插件可使用自有样式。字号、行高、间距等可能改变布局，不能作为无风险的纯配色更新处理。

### 17.3 第三方 UI 的两种模式

**宿主组件模式**：插件声明字段和组件，宿主统一渲染，自动适配主题。第三方通过受支持的布局和样式选项定制，不使用全局 CSS 选择器覆盖宿主内部结构。

**自定义 UI 模式**：插件提供 HTML/CSS/JS，自行设计曲线、时间轴、蒙版、多图操作等面板，仍通过 SDK 读写参数、提交任务和接收结果。可以采用宿主主题变量，也可以保持自有外观；manifest 声明主题适配能力。

混合使用时通过受支持的组件桥或 SDK 视图能力实现，不允许自定义视图跨来源直接操作主画布 DOM。可复用组件需要声明作用域和版本，避免不同插件用同名样式或组件互相覆盖。

### 17.4 样式隔离与宿主边界

节点外壳、标题操作区、选中与错误状态、连线端口、拖动和缩放边界由宿主管理。插件设计节点内容区和经批准的专用面板；需要新的外壳布局时通过宿主声明接口扩展，不直接覆盖宿主 CSS。

自定义 UI 使用第 15 节验证过的 iframe/WebView 隔离方案。宿主通过消息桥发送有版本的主题 token 快照及变化通知，视图映射为自己的 CSS 变量；变量使用语义名称并提供缺省值。插件内部 CSS 不注入主文档，主题 token 也不携带可执行脚本或任意样式文本。

插件通过 SDK 请求内容尺寸，宿主实施最小/最大尺寸、滚动及缩放策略，避免第三方节点遮挡画布或无限扩张。明确键盘焦点、指针事件、快捷键和拖动事件归属，不能因隔离视图抢焦点而使画布操作失效。

### 17.5 验收与阶段补充

将版本化组件目录和依赖锁定纳入 D1；第三方专用样式、主题桥及尺寸/焦点协议纳入 D2；AI 生成两种 UI 模式及兼容升级测试纳入 D3。至少验收：

- 旧节点在组件升级后仍使用兼容实现；不兼容迁移失败可回退，数据及连线完整。
- 共享组件调整字体、间距及按钮尺寸后，在声明支持的节点宽度、缩放和显示比例下无溢出、遮挡或不可点击。
- 主题切换时，采用主题的节点更新，自有样式插件保持其声明行为；主题协议新增变量时旧插件有回退值。
- 一个插件使用通用标签选择器或同名 class 时，不改变主画布及其他插件样式。
- 自定义 UI 的输入、焦点、拖动边界、尺寸调整及应用重启恢复正常。
- 导入缺失组件或不兼容版本时保留占位节点；补齐依赖后可以恢复。

上述为新增架构要求，不代表当前所有内置节点已经具备版本隔离或第三方样式支持；实际迁移逐个核对，并按修改影响执行必要验证。

## 18. 节点分类分组与菜单查找

### 18.1 目标与范围

支持给节点类型创建分类分组，在添加节点菜单中按分组浏览和搜索，覆盖内置节点、第三方插件节点及 AI 创建的节点。此处是节点目录分类，与画布上将多个节点框选成组的功能分开。

用户可以新建、重命名、排序及删除自定义分组，将节点加入或移出分组；一个节点类型可属于多个分组，不复制节点实现。删除分组只移除分类关系，不删除插件、节点类型或画布中的节点。

### 18.2 目录和分类数据

以第 16 节经过校验的节点注册目录作为唯一能力来源，菜单读取同一目录，不另写一份可用节点白名单。节点元数据增加显示名称、简介、搜索关键词、可选图标及推荐分类；使用稳定 typeId 关联，不能用显示名称作为标识。

分组记录稳定 ID、显示名称和排序，成员关系独立保存。首版使用平级分组，避免过深菜单；默认可提供图像、视频、音频、文本、数据、工具等分类，实际名称和数量按节点情况确定。

插件只声明推荐分类，宿主映射到已存在分类或“未分类”，不允许安装时任意创建大量菜单项、覆盖用户分组或占用内置分组 ID。用户归类优先于推荐分类，插件更新不重置用户调整。

分类和排序保存于应用用户数据目录，重启后恢复；属于用户目录偏好，不改变节点运行定义。导入导出插件或画布时可以携带推荐分类，但不能无提示覆盖本机目录组织。

### 18.3 菜单交互与搜索

添加节点菜单提供“全部”、分类列表和搜索入口；支持按名称、关键词、插件名称查找，搜索命中不重复显示同一节点。搜索明确显示当前范围，可在当前分类筛选或切换全部范围，避免节点因分类位置不同而找不到。

每项展示名称及必要的来源标识；同名节点通过插件名区分。点击创建时仍调用宿主节点工厂及权限检查。支持键盘选择、确认和关闭；窄窗口下分类与结果可滚动，不遮挡主要操作。

AI 创建新节点时可以提出推荐分类；用户也可以要求“把这些节点归到商品处理组”。AI 修改用户分类使用独立的结构化目录操作，验证节点/分组 ID 并遵循已有授权，不通过改插件文件实现。

停用、缺失或不兼容的节点默认不混入可创建列表，可在节点管理中查看原因；已保存的分类关系保留，恢复插件后重新出现。安装新节点后更新菜单，无需重新构建桌面软件；若该插件需要应用重启，明确提示生效时机。

### 18.4 验收与阶段归属

分类数据与目录接口纳入 D1，内置及第三方节点菜单接入纳入 D2，AI 推荐分类及目录操作纳入 D3。验收覆盖：创建/重命名/排序/删除分组、多分组成员、搜索同名节点、用户分类不被插件升级覆盖、停用后恢复、应用重启持久化及创建行为正常。

分类变化不得改变节点参数、端口、执行版本或已有画布数据。首版无需另加收藏、云端同步或多层目录，后续有明确需求再扩展。

### 21.2 UI 与样式隔离

iframe 仅授予 `allow-scripts`，不授予 `allow-same-origin` 或 Tauri 权限；CSP 禁止外网连接和远程脚本。父桥校验空来源、窗口、随机会话及字段类型/范围。脚本不进入主画布或 iframe DOM，超时终止 worker。该模式支持颜色、曲线等自定义参数交互；不是任意 HTML 网站或完整第三方前端框架加载器。

### 21.3 桌面独立执行与节点包

`core/node_worker.py` 使用桌面随附 Python 独立进程执行，stdin 接收 `{protocolVersion:1,params,inputs}`，stdout 返回 `{protocolVersion:1,outputs:{text}}`。限制源码 8000 字符、单次 1—30 秒、候选总执行预算 60 秒，stdout/stderr 各 64 KiB。取消及超时回收本任务进程树，不继承宿主凭据环境变量。

`core/node_plugin_package.py` 生成和验证 `.artnode` ZIP；固定文件白名单、API/组件版本、权限、文件及定义 SHA256。压缩包上限 256 KiB，内容上限 1 MiB，拒绝重复条目、路径穿越、链接、加密及异常膨胀。校验不解压任意路径；完整性哈希不代表作者可信。

## 22. 第四批：扩展节点的静态图片输入输出（2026-11-04）

### 22.1 协议与资源

沿用 `worker.python`，仅新节点显式设置 `execution.media: true` 时启用图片协议 v2。未设置或为 false 的旧文本 worker 保持协议 v1，定义归一化移除默认 false，不改变已安装节点的定义哈希。

v2 stdin 结构：

```json
{"protocolVersion":2,"params":{},"inputs":["上游文本"],"images":[{"id":"资源ID","path":"images-in/0.png","width":96,"height":64,"sha256":"内容摘要"}],"outputDir":"images-out"}
```

v2 stdout 结构：

```json
{"protocolVersion":2,"outputs":{"text":"处理说明","images":["images-out/result.png"]}}
```

宿主 `core/node_media.py` 创建账号绑定的随机资源 ID，元数据保存在用户数据目录 `node-plugins/resources/<账号摘要>`，图片通过既有媒体目录规则保存。资源 ID 只允许当前账号读取，读取时核对内容哈希；worker 获得的是自身临时目录内的图片副本，不接收外部 URL 或用户传入的任意本机路径。图片展示 URL 沿用现有 `/output` 机制，不能把资源 ID 隔离误述为新增了完整的公开媒体 URL 访问控制。

导入仅接收静态 PNG/JPEG/WebP/BMP 的 Base64 data URL，限制单图 8 MiB、1600 万像素，拒绝动画与解压炸弹并归一化为 PNG。每次最多 8 张输入及 8 张输出，输出文件总量最多 32 MiB。输出必须是 `images-out/` 的简单文件名，拒绝目录穿越、绝对路径、软/硬链接、重复文件和坏图；先校验整批，再发布，取消或发布失败清理本批已发布资源。执行期间检查图片目录的文件数量和大小；这些检查不是对可信代码在操作系统上所有文件写入的强制磁盘配额。

可信 Python 代码的授权要求保持不变。Pillow 复用现有依赖和桌面随附 Python，不引入依赖管理器或要求用户安装全局 Python。

### 23.1 定义与 AI 工具

### 23.2 安装与资源边界

新增 `core/node_python_env.py`。仅从 `pypi.org` 和 `files.pythonhosted.org` 的 HTTPS 接口读取元数据或下载，重定向同样检查域名；不使用环境中的代理、凭据或其他索引配置。只选择非撤回且兼容当前 Python 标签的 wheel，不执行 sdist、setup.py、构建后端或任意安装脚本。

### 23.3 隔离、版本与恢复

环境位于用户数据目录 `node-plugins/environments/<账号摘要>/<定义及Python摘要>`；账号、完整定义哈希、应用 Python 路径/版本/平台共同确定环境。新节点版本或依赖变更建立新目录，旧目录不覆盖，旧节点可继续运行旧依赖；准备成功后原子移入最终目录，保存 environment.json，后续复用，不重复下载。

有额外依赖的 worker 使用 `-I -S -B` 和显式标准库/独立依赖搜索路径，移除宿主 site-packages、桌面 app 路径和用户 Python 路径；不执行目标目录中的 `.pth`。这意味着图片节点一旦声明独立依赖，也必须显式包含 Pillow 及它需要的包，不能隐式借用宿主 Pillow。未声明额外依赖的旧节点保持原有随附运行时行为，空 dependencies 字段在定义归一化时移除，旧哈希不变。

同一账号同一环境使用排他租约，拒绝并发重复安装。状态包括 missing、resolving、downloading、installing、ready、failed、cancelled；有租约时查询返回 busy，已发布目录不完整返回 damaged。ready 仅指环境安装完成，不等同于节点测试通过。进程异常退出遗留租约时保守报告需核对，不自动删除锁或覆盖可能仍在使用的目录；此批未提供自动恢复中断安装或环境垃圾回收功能。

环境隔离只隔离正常 Python 包搜索和安装目录，**不是操作系统沙箱**。已经授权的 Python 代码仍能主动访问当前用户文件、网络和创建进程，也可能主动修改其他目录；不能据此宣称能安全执行任意未知代码。

### 23.4 节点包与使用入口

### 26.1 凭据与执行边界

定义只保存 `credentialRef` 用途名称，不保存真实密钥。用户在画布节点中看到目标 HTTPS 地址、费用和失败不重试说明，再通过密码框“绑定凭据并授权”。凭据仅通过主机本地、已登录、同源且带 X-Art-MCP 的专用接口提交；状态查询只返回 configured。密码提交后清空，不写入节点对象、画布、AI 快照、候选测试或 `.artnode` 包。

宿主在当前账号摘要与完整定义哈希下单独保存凭据；不同账号、节点版本、目标地址或任何定义变化均不能复用绑定。导出包只携带 `http-post`、`credential-reference` 权限声明，接收者必须重新绑定。可在节点面板解除绑定。存储沿用本机用户数据目录与原子 JSON 写入方式，文件权限设为仅当前用户读写（Windows chmod 不等同于 ACL 隔离）；**本批未提供系统密钥链或磁盘加密**，同一系统用户下的可信 Python 代码仍可能读取本机文件。

执行时宿主注入 Authorization: Bearer，不把密钥交给 worker 或 AI。不接受 URL 中的 query、fragment、userinfo，不使用环境代理、不跟随重定向、不自动重试。只接受 2xx；非成功响应不回传服务响应正文，网络错误不暴露底层含认证信息的异常。结果若原样包含已注入密钥则不发布。此检查不是任意编码或变形泄露的完整防护。

响应最多 1 MiB，提取文本最多 16000 字符；超时参数 1—30 秒，网络 I/O 使用该超时，并在接收分块时检查总耗时。同步调用不能保证远端即时取消，超时/断线不代表远端未执行。调用本身可能收费，本批不提供费用预算、幂等键、远端状态查询或安全自动重试。请求头/内容不进入执行报告。

## 27. Windows API 凭据系统加密（2026-11-04）

## 29. 受管下载中断后的文件恢复核对（2026-11-04）

受管模型的“核对”现在会重新读取本机完整文件，按已批准计划验证容量和SHA256，再检查加载器；不再只信任已有下载回执。软件在文件发布后、回执落盘前中断时，也可通过同一入口恢复：文件必须完整匹配固定哈希，否则不认定成功。此恢复过程不发送下载请求、不覆盖或删除已有模型；文件缺失或损坏提示人工处理，不静默重下。

新增 verify_existing，复用标准模型路径映射并拒绝符号链接目标。读取采用1MiB分块，检查文件句柄及路径各自的前后大小、时间和标识，期间发生变化则拒绝。Windows句柄与路径查询可能具有不同标识格式，因此只比较同类查询的前后状态。成功保存新的downloadReceipt及recheckedAt；面板展示已校验字节数，并将受管任务核对按钮标为“重新校验文件和加载器”。

只恢复当前本工具启动、目录与计划匹配的原实例；软件重启后需先恢复受管ComfyUI实例。不会仅凭旧回执或模型枚举跳过文件校验。不提供断点续传、自动重试或孤儿.part清理，也不对已成功任务持续扫描；重新核对完成后其他程序仍可能修改文件。该检查不是操作系统级文件锁或对抗同用户恶意程序的安全保证。

验证：下载器和安装组17 passed、1 skipped、5 subtests；覆盖无网络恢复、无旧回执恢复、同大小文件篡改、预算超限、文件缺失、保留原文件与加载器核对。既有可选真实环境测试跳过。前端JS语法及ComfyUI构建测试通过；未运行真实模型或桌面安装器验收。

## 30. PCM WAV 通用音频端口（2026-11-04）

命名端口新增audio类型，仅支持16位PCM WAV，单/双声道、8000—192000Hz、最长300秒、单项不超过8MiB。与图片/蒙版共享每次最多8项媒体、输出总量32MiB的现有限制。宿主用标准库wave解析真实帧数据，拒绝无效/截断/编码不支持的文件并重新编码成规范WAV，不依赖系统FFmpeg或ComfyUI。

账号资源沿用NodeMedia目录、资源ID、内容哈希、所有权校验和worker暂存副本。音频输入描述包括kind/type、path、frames、sampleRate、channels、duration和sha256；worker必须声明execution.media=true，仍使用命名协议v3。为复用原有受限输出目录，此批音频文件也写到images-out/下，返回outputs中的命名音频端口，不能把本机任意绝对路径作为输出。音频不会混入旧outputs.images集合；相同文件不得同时声明图片与音频。

候选测试支持portInputs中以{frames,sampleRate,channels}生成确定性静音WAV（最多48000帧、48000Hz），expectedPorts比较真实输出的frames/sampleRate/channels及可选sha256。候选的测试素材不是音色、内容或语音语义质量验证。SDK、组件schema与AI候选工具测试说明同步更新。

画布音频端口提供WAV上传、移除及播放，输出使用audio controls展示；上传资源引用保存在extensionPortInputs并随节点保存，执行时将引用转为账号资源ID。音频节点之间继续通过bindings映射，支持已有集合索引协议；音频与图片/蒙版不隐式转换。新增import-media动作别名并保留旧import-image入口兼容。

示例：docs/examples/node-audio-wav.json及.artnode。示例为读取800帧音频并原样输出的可信worker，用于验证通道协议，不是语音生成器；运行真实输入时同样要求800帧。

验证：音频、原图片资源、候选组合22 passed、24 subtests，包含真实独立worker通过标准库wave读取音频并输出文件、跨账号拒绝、损坏/截断WAV、错误媒体引用、音频图片类型不兼容与候选素材测试。AI端口与SDK相关4 passed、8 subtests。新增前端音频端口测试、既有端口映射及图片节点测试、JS语法检查通过。未做真实浏览器试听或桌面安装器验收；MP3/AAC、视频、内置音频生成节点与此协议的全部适配仍未完成，不能称为音视频支持全部完成。

## 31. 现有音频节点接入通用音频端口（2026-11-04）
