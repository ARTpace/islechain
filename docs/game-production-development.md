# 游戏工程、数据、测试与交付：开发流程

> 更新：2026-11-02；状态：部分实现，G—N 尚未全部验收。
> 需求：[后续需求文档](game-production-requirements.md)。前置：[首期开发流程 A—F](game-pipeline-development.md)。
> 本文从 G 编号，形成连续路线；每阶段以门槛推进，不以代码量或固定周数计完成。

## 1. 执行约束与依赖

- 先复用首期项目身份、权限、文档、资产及导出能力，不另建平行项目系统。
- 首期未完成时可以做技术验证与合同设计，但不得宣布下游集成验收通过。
- 当前已接入工程、数据、构建、测试、备份与交付模块，不再仅有纯合同；实际能力、检查和未完成项见文末与测试开发文档，不代表全部阶段通过。
- 先一套 Web 2D 模板、一个主执行 Agent、一个本地运行环境，再考虑其他引擎。
- 宿主无需更换前端框架，不先做全量存储重构、数据库或插件平台。
- 沿用 ponytail-build、项目 AGENTS.md 和 docs/README.md；不覆盖无关工作区修改、不自动提交或重启。
- 下述模块名与 API 是待冻结建议，不是已经存在的能力。

## 2. 阶段 G：工程合同、技术栈与安全验证

工作：

1. 检查首期验收记录，核对真实 Plan、Asset、Selection 字段，不只照抄设计文档。
2. 确定 requirementId、caseId、taskId、runId、buildId、snapshotId 与各 revision/hash 的关系。
3. 为文本验收条目设计显式 schema 升级，备份并保留旧文本映射；严格模型拒绝未知字段，不能直接扩字段上线。
4. 验证 TypeScript + Phaser + Vite 候选模板：最小游戏、依赖锁、构建、启动、资源路径、基本输入及打包。
5. 评估一个成熟 Agent 执行引擎的工具、取消、恢复、日志、权限和分发许可；未满足时暂不接自动执行。
6. 确认运行隔离方案、宿主权限边界与预览来源；形成执行权限表。只设 cwd 不算隔离。
7. 固定内容数据 schema、状态机、文件大小/日志/任务/证据上限及接口模型。

交付：合同、模板验证结果、执行引擎结论和安全边界。技术验证使用隔离样例，不写用完即删的探针脚本；能复用现有工具时直接诊断。

门槛：模板真实构建和启动；无可执行隔离方案则允许继续文件/数据功能，但阻止无人值守执行阶段。

## 3. 阶段 H：工程文件与最小恢复点

工作：

1. 项目创建单一 game 工程，文件浏览、文本读写、搜索和差异查看。
2. 所有路径服务端验证项目根边界，覆盖 symlink/junction 逃逸；读写校验 owner。
3. 保存基于 hash/revision，检测外部编辑，冲突时保留双方内容。
4. 建立最小文件快照：变更前记录源码、策划和资源输入，失败可恢复。
5. 多文件补丁在暂存目录校验后采用，防止部分写入；恢复前保护未保存修改。
6. 首期选用文件按 manifest 解析到工程，记录来源版本，不写回原始素材。

检查：相关文件服务测试覆盖越权、逃逸、冲突、补丁中断和恢复；界面验证手动修改与重开。

门槛：不用 Agent 也能查看和安全修改工程；原项目与首期美术功能仍兼容。

## 4. 阶段 I：游戏配置与数据编辑

工作：

1. 以角色、敌人、关卡三个样例数据集实现 schema、稳定行 ID 与 revision。
2. 基础表格/表单、字段错误、增删行、差异和 JSON 导入导出。
3. 类型、范围、唯一、跨表引用及 assetId 校验；被引用项不直接删除。
4. 构建前将合法内容数据导入游戏，并保留输入清单。
5. AI 数值修改先产出候选差异，不能跳过校验自动覆盖。
6. CSV、复杂表达式、通用可视化脚本暂不引入，避免首条链路过度扩张。

检查：直接相关数据测试覆盖非法类型、引用缺失、删除限制、冲突和导入往返；界面修改速度并预览差异。

门槛：数值数据有独立可验证的存储与编辑路径，不靠改代码常量实现。

## 5. 阶段 J：构建、运行与隔离预览

工作：

1. 受控模板命令执行器，记录输入版本、退出码、日志与产物 hash。
2. 运行状态 queued/starting/running/stopping/succeeded/failed/cancelled/interrupted；区分服务器启动和构建成功。
3. 管理本系统拥有的进程树、端口和运行目录，限制超时与输出，停止不影响其他项目。
4. 页面刷新可重新连接；服务重启后核对进程归属，不能核实时标 interrupted，不自动重复运行。
5. 隔离来源预览、sandbox/CSP、资源加载诊断、错误与拒绝日志；消息绑定来源窗口和运行令牌。
6. 锁定依赖并限制构建环境网络与凭据；依赖安装脚本按可执行代码处理。
7. 失败保留最后可用构建，预览切换显式指向 buildId。

检查：正常构建、错误构建、端口冲突、超时、停止、重连、伪造消息、跨项目预览；真实打开样例验证加载与输入。

门槛：人工编写样例能安全运行，日志准确；隔离未落实不得开放任意 Agent 命令。

## 6. 阶段 K：执行 Agent 与灰盒制作

工作：

1. 接入阶段 G 选定引擎，只提供当前需要的文件、资产、配置、构建和运行工具。
2. 从确认策划产生任务候选，包含依赖与验收；用户可改计划，已授权步骤连续执行。
3. 一个工程只允许一个自动写任务，补丁前核对基线；手工编辑冲突时停止采用。
4. 固定输入快照，建立 taskId/runId/toolCall 的记录与有界日志，密钥脱敏。
5. 完成灰盒：移动、收集、敌人扣血、胜负、重开；再整合正式选用资源。
6. 支持取消与中断恢复，不把会话恢复等同于盲目重放副作用；任务重试先查已有结果。
7. 生成新依赖、外部访问和工具越权按权限边界处理，不以模型输出直接获得执行权。

检查：模拟模型覆盖工具参数、拒绝、失败、冲突、取消和重复回调；真实模型在授权后完成一次灰盒及局部修改。

门槛：同项目可连续开发，不靠整份覆盖；任务成功有构建/检查证据，不只靠模型声明。

## 7. 阶段 L：玩法测试与问题修复

具体子阶段见 [测试开发 T1—T8](game-testing-development.md)，验收依据见 [测试需求](game-testing-requirements.md)。T1 与 G 对齐，运行部分依赖 J，存档部分依赖 M，报告与 N 对齐；不要求所有后续能力完成后才开始核心测试。

工作：

1. requirementId 关联 caseId，提供前置、输入、预期与执行方式。
2. 接入浏览器运行工具执行键鼠、截图、日志采集；测试数据与随机种子可固定时记录，无法固定时说明。
3. 首批用例：启动、移动、收集、扣血、胜负、重开、资源加载和声明支持的窗口尺寸。
4. 保存 buildId/runId 对应的证据；区分 automated/agent/manual，blocked/not_run 不计通过。
5. 用户试玩反馈关联当前构建与截图，建立问题、修复任务和回归用例。
6. 修复前快照、定向补丁、受影响用例及核心冒烟；三轮仍失败按需求规则停止自动循环。
7. 截图涉及模型判断时标注判断来源；美术与乐趣保留人工验收。

检查：故意引入“失败后重开未重置状态”，确认可复现、记录、修复并回归；验证旧证据不能冒充新构建通过。

门槛：存在真实操作与问题关闭证据；不以无异常日志替代可玩验证。

## 8. 阶段 M：存档与完整版本恢复

工作：

1. 版本化本地存档、保存载入、测试独立槽、清空与损坏恢复。
2. 存档升级策略与不可兼容提示，重置前保留备份；重开和清档按策划区分。
3. 将阶段 H 的最小快照扩展为策划、数据、素材选择、源码及锁文件的一致恢复点。
4. 恢复使用暂存和完整性校验，生成新的当前 revision；审计和历史问题证据不倒退。
5. 备份导入新项目 ID 并重建 owner/画布关联，校验包内路径和 hash，不执行包内脚本。
6. 建立引用查询供人工清理使用，本阶段仍不自动垃圾回收。

检查：存档旧版/损坏、测试隔离、多文件恢复中断、手工修改保护、备份往返和导入越权。

门槛：能够恢复可运行版本，测试不污染正常存档；备份不是仅包含元数据的空包。

## 9. 阶段 N：发布前检查与交付包

工作：

1. 生成 Web 运行包、源码包与项目备份包，标明不同用途。
2. 汇总需求覆盖、构建、资产、数据、玩法和设备检查，显示阻断项与已知限制。
3. 正式完成需无未解决阻断项；开发版导出明确标记，不隐藏失败。
4. 导出排除凭据、个人存档、node_modules 与临时记录，保留必要许可证和素材来源。
5. 在干净目标环境按说明启动 Web 包、按锁文件构建源码；依赖网络需求如实标注。
6. 完成后续需求十一项验收；本阶段不自动上传或公开发布。

门槛：用户拿到可运行、可继续修改、可恢复的工程与测试摘要。未验证的平台不宣称支持。

## 10. 建议模块与接口

后端职责可按真实复杂度落入工程文件、数据、任务运行、测试问题和快照导出模块；优先复用首期路由/服务，不先按每个名词创建框架。Agent 适配层只实现选定引擎。

全部路径沿用 /api/game-projects/{projectId}，写操作校验基线、owner 和 schema；以下为能力合同，方法与字段在 G 冻结。

| 资源 | 最小操作 |
|---|---|
| engine-project | 模板创建、配置读取 |
| files / patches | 列表、受限读取、hash 写入、补丁预览/采用 |
| datasets | schema/数据读写、校验、导入导出 |
| tasks | 计划、开始、查询、事件游标、取消、明确恢复 |
| builds / runs | 构建、启动、状态、日志游标、停止 |
| test-cases / test-runs | 用例管理、执行、证据和结果 |
| issues | 创建、关联修复、回归后关闭 |
| snapshots | 创建、差异、恢复 |
| backups / exports | 创建、授权下载、校验导入 |

预览与玩家存档不直接使用宿主项目写接口。任务事件按游标增量读取，不无界轮询整份日志；未实现的能力不提前注册空壳端点。

## 11. 验证、记录和停止条件

- 每阶段仅运行直接相关测试和项目强制检查。宿主 Python 路由变更检查隔离导入与注册；模板 TypeScript 修改运行相应 check 与直接相关测试。
- 游戏测试与宿主功能测试分开记录，不对文档更新执行游戏构建。
- 模拟上游验证协议，真实模型验证实际工具链；两者不互相冒充。
- 安全隔离、进程归属、并发写入及恢复属于具体高风险点，按用例验证，不因减少检查省略。
- 检查记录实际命令、退出码、构建/运行版本、设备、通过/失败/跳过，结果有效时不重复。
- 环境或渠道阻塞有限诊断，不反复重试；阶段门槛未通过保留未完成状态。
- 无关历史失败只记录，不扩范围；用户已有改动不覆盖，不自动清理或提交。

## 12. 后续扩展顺序

### 源码对照后的阶段补充

详见 [源码经验、调用点与测试证据](ohmygame-source-lessons.md)。G/H 增加 workspaceEpoch 与恢复排除清单；J 增加父进程退出后代存活、启动失败和 PID 归属验证；K 增加跟随任务的取消归属、恢复通知与上下文重读；L 增加会话归属、等待进行中的 open 后清理、能力检查及可选确定性 bridge；M 增加未完成恢复写入封锁、不可读路径保护及旧会话失效。先验证这些行为，不直接移植上游多运行时或对象库架构。

完整 Web 2D 链路稳定后，按真实用户需求依次评估更多模板/3D/动画、已有工程导入、Unity 或 Godot 适配、协作与 Git、云构建与发布、联机后端。每个引擎需要自己的构建、运行、资产导入和测试协议，不能仅增加下拉选项宣称支持。

完整恢复同时恢复策划、文档、内容数据、源码和资产选择；项目/策划/资料修订递增、epoch 递增，候选/输出与测试审计不倒退。选用文件按历史不可变路径/hash 校验，文档正文从已校验模型重建。检测外部文档修改或不可读文件时拒绝覆盖。`restore-pending.json` 存在时普通项目入口拒绝访问，只有授权事务查询和显式继续/回滚可用；失败不会伪装成完整恢复。
