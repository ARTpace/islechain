# IsleChain 项目结构与复用优化开发方案

日期：2026-11-19  
状态：已开始第一批迁移。本文其余目标结构与阶段清单仍为计划，不代表全部完成。

首批进度：已原样外置 zimage 的两块主要样式；抽取图片卡片创建及思考过程展示；轮次导航补齐重复挂载保护和 dispose；相关 Node 检查接入 CI。完整消息操作、会话管理和全站缓存生命周期尚未迁移。实际界面效果及性能指标尚未测量。

续批进度：用户/助手消息节点、参考图展示和时间展示已迁入 ChatTranscript，通过容器与业务回调隔离实例。新增消息纯文本与实例隔离测试，历史恢复及分页测试接入展示 CI。发送、生成、消息操作和会话持久化仍由页面负责。

## 1. 目标与边界

优先改善界面一致性、页面切换体验、公共功能复用和变更可靠性，逐步降低大文件与隐式依赖带来的维护成本。

- 沿用 FastAPI、原生 JavaScript 和 Tauri，不为重构引入新框架。
- 保持现有接口、用户数据格式、生成任务及恢复行为兼容。
- 保持主要操作直接可达；选择、切换、预览不增加菜单层级或确认。
- 每次只迁移一个职责，避免同时修改展示、请求协议与存储格式。
- 不直接修改打包产物；不未经引用核实删除历史文件、依赖或配置。
- 提示词采集及发布仍由独立 Art-prompt-library 仓库维护。

## 2. 当前结构与证据

以下为静态检查时的近似规模，随开发变化，不作为拆分硬指标。

| 位置 | 现状 | 优化方向 |
| --- | --- | --- |
| `main.py` | 约 9,800 行；许多路由反向导入入口 | 提取业务能力，入口保留装配 |
| `static/js/smart-canvas.js` | 约 19,500 行 | 按画布状态、节点、交互、任务逐步划分 |
| `static/js/canvas.js` | 约 14,600 行 | 先明确共享契约，再迁移公共能力 |
| `static/app/zimage.html` | 约 7,400 行；混合布局、样式、对话与生成 | 优先拆展示与媒体，再拆会话及调度 |
| 主题与组件样式 | 多份主题 CSS、页面内联及运行时样式共同参与 | 固定职责，减少跨层覆盖 |
| 页面缓存 | 主界面保留多个 iframe，画布管理页保留编辑器 | 配套暂停、恢复、释放 |

当前未测量首屏、切换耗时、内存或后台请求量，不能据此承诺性能提升比例。依赖是否未使用、旧副本是否可删除，需要专项核实。

## 3. 目标模块边界

### 3.1 前端层次

```text
页面入口：装配、布局、页面专属配置
    ↓
业务模块：对话生图、画布编辑、API 设置
    ↓
公共组件：消息展示、媒体卡片、模型选择、输入栏、导航
    ↓
基础工具：请求、订阅、格式转换、资源加载
```

公共模块优先扩展现有 `static/modules/` 实现。只被单个页面使用的业务代码不应为了“通用”而强行提升为公共底座。

组件接收明确的容器、数据与回调，不读取其他页面的私有 DOM 或可变全局变量。新组件采用局部样式命名，避免覆盖通用 `button`、`img`、`header`。

### 3.2 对话生图拆分

以下名称为建议，实施时先核对同名或同职责模块。

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `zimage.css` / `chat-layout.css` | 页面布局及响应式 | 公共主题值、业务状态 |
| `chat-transcript.js` | 消息节点、时间、思考展示、复制及消息操作 | 平台配置、生成请求 |
| `chat-media.js` | 图片实际比例、加载状态、预览与媒体操作入口 | 会话持久化、任务轮询 |
| `chat-conversations.js` | 历史分页、新建、载入、删除、恢复 | 消息正文解析 |
| `chat-session.js` | 发送、流式读取、取消、会话请求状态 | 图片卡片布局 |
| `chat-image-generation.js` | 对话结果到生成请求的转换及降级 | 通用 Markdown 渲染 |

继续复用现有模块：

- `content-preview.js`：正文与内容卡片渲染。
- `chat-outline.js`：轮次导航及跳到最新消息。
- `chat-tasks.js`、`card-progress.js`：先核实已有任务、进度契约，避免重复实现。
- `chat-video.js`：视频展示。
- `model-picker.js`、`image-generation-workflow.js`：模型与生图能力。

拆分顺序：CSS → 消息展示 → 媒体卡片 → 会话管理 → 请求与生成衔接。复杂发送流程放在后面，避免先拆出大量相互调用的全局函数。

### 3.3 后端依赖

```text
main.py：应用启动、中间件、生命周期、路由注册
    ↓
routers/：参数校验、身份上下文、响应与错误映射
    ↓
业务模块：平台配置、模型目录、生成调度、会话存储
    ↓
core/ 中符合 CODEMAP 约束的通用工具
```

新增业务模块放在对应业务包；`core/` 不作为大文件迁移的杂物目录。优先提取平台配置读写及模型目录，让路由与生成服务共同依赖它们，逐步消除 `routers → main` 反向依赖。

不得在第一轮同时修改 API 路径、密钥存储、权限模型或任务持久化格式。

## 4. 样式统一方案

| 层级 | 负责内容 | 限制 |
| --- | --- | --- |
| 主题变量 | 色彩、透明度、圆角、阴影、间距尺度 | 不包含业务页面选择器 |
| 公共组件 | 按钮、开关、表单、卡片及交互状态 | 不定位某个页面的元素 |
| 业务布局 | 聊天、画布、设置页排列 | 不复制整套主题规则 |
| 页面特例 | 独有控件 | 限定作用域，写明必要原因 |

先梳理 `static/theme.css`、`static/css/theme.css`、`studio-ui.css`、`studio-controls.css`、`appearance.css` 的实际加载顺序及覆盖关系，再逐批迁移。不能直接删掉任一文件或批量移除 `!important`。

样式验收：深浅主题、主要强调色、桌面缩放及窄屏下，主操作呈现柔和底色、细描边和可读文字；危险、禁用、忙碌、选中状态仍可区分。按钮操作路径和点击次数保持不变。

## 5. 页面与组件生命周期

按需要支持以下轻量约定，不要求每个纯函数实现完整生命周期：

| 阶段 | 行为 |
| --- | --- |
| `mount` | 创建 DOM、注册监听、首次读取 |
| `activate` | 恢复可见页面的更新，按失效标记刷新 |
| `deactivate` | 暂停非必要轮询、动画和观察器更新 |
| `dispose` | 解绑监听、取消计时器、释放观察器和媒体资源 |

iframe 可通过同源方法或明确的消息协议接收激活状态；若使用消息，校验来源与发送窗口。不要仅依赖 `document.hidden` 判断缓存 iframe 是否活跃。

规则：

- 页面隐藏不等于取消生成；任务继续，展示更新可暂停。
- 切换会话后，旧请求回调不能写入新会话。
- 重复激活不能重复创建计时器、监听或订阅。
- 保存、生成、取消等进行中状态必须有明确归属。
- 缓存淘汰先检查未保存修改和进行中任务，避免因释放页面丢数据。
- 返回管理页保留列表位置、缩放及选择；配置或任务有变化时定向刷新，避免复用旧页面导致数据过期。

## 6. 构建与缓存

1. 盘点实际加载的源码、构建产物、内联脚本及第三方资源。
2. 明确 `esbuild.config.js`、`scripts/build.mjs` 与各独立工具构建入口的职责。
3. 优先为新拆出的模块建立统一入口；迁移期间兼容现有页面。
4. 用内容哈希或统一资源清单替代分散的手写日期版本号。
5. 重型编辑器、3D、音视频处理等资源按进入对应功能时加载。
6. 发布时保证 HTML 与资源版本一致，并保留可回退版本。

不能仅因源码中出现重复库名就删除资源；先核实不同 iframe、独立页面及构建边界。

## 7. 分阶段执行清单

| 阶段 | 任务 | 完成条件 |
| --- | --- | --- |
| A：基线 | 记录入口、数据归属、资源加载、关键行为及必要性能指标 | 可对比迁移前后，有明确基线 |
| B：公共展示 | 分离 zimage 样式、消息及图片展示；收敛公共按钮样式 | 原行为兼容，在另一个实际调用方验证复用 |
| C：生命周期 | 为缓存页面补齐激活、暂停、释放及定向刷新 | 不重复监听，不丢任务，返回位置保留 |
| D：会话业务 | 拆会话管理、请求与生成衔接，消除隐式状态共享 | 发送、取消、切换、恢复及错误路径正确 |
| E：后端解耦 | 提取平台配置与模型目录，再评估生成调度 | 迁移路由不再依赖 main 中的对应实现 |
| F：构建收敛 | 接入资源清单、统一检查与发布构建 | 无漏更新资源，构建可重复 |
| G：清理 | 核实旧副本、未使用入口及依赖 | 有引用证据、备份及回滚方式后再删 |

不按文件行数设强制拆分目标，不预估未经测量的代码减少量或加速比例。

## 8. 验证与性能基线

### 行为验收

- 普通对话、流式回复、Markdown 与代码卡片展示正常。
- 生成图按实际比例展示，加载、预览、复制、引用和下载入口可用。
- 查看历史时不被流式回复强制拉底；轮次导航和跳到最新位置正常。
- 切换、删除、新建和恢复会话不会串消息或写错目标。
- 画布管理页与编辑器往返不强制重建列表，后台任务可恢复。
- API 自动保存的连续修改、请求失败及页面切换不丢配置；不泄露密钥。
- 权限、访客模式及独立页面入口保持兼容。

### 性能记录

在同一设备、相同数据和窗口状态下比较：冷启动、首次进入对话、历史恢复、画布往返、连续切换后的内存、空闲后台请求数。记录冷缓存与热缓存、样本数量及数据规模。

测量后再为具体阶段设置预算；静态文件变小、计时器减少不直接等同于用户感知变快。

### 检查策略

- 样式微调通常只检查 diff；涉及布局迁移时补实际视觉验证。
- JS 迁移运行语法检查和直接受影响的测试，新增测试优先验证行为而非源码字符串。
- Python 迁移运行对应路由或业务模块测试。
- CI 增加 Node 运行环境及现有 `.cjs` / `.mjs` 测试入口；不能仅添加 Node 后仍只运行 pytest。
- 对关键页面保留少量交互回归，覆盖布局、滚动、缩放和生命周期；纯 DOM 模拟测试不能代替这些检查。
- 只跑必要检查；无后续变更或新风险时不重复运行。

## 9. 变更与回滚

当前工作区存在大量既有修改。开始每个阶段前记录相关 diff，不把无关修改混入迁移，不批量还原文件。

- 每个阶段提交一个可独立审阅、验证和回退的职责迁移。
- 首批保留旧页面调用契约，通过薄适配接到新模块；迁移完成后再移除适配。
- 如涉及配置数据，先备份并说明恢复方式。
- 更新 `CODEMAP.md` 的功能归属与模块路径。
- 同一问题两轮修复无效时重新定位；第三轮必须有新证据，仍失败则停止扩展修改并记录阻碍。

## 10. 第一批建议范围

第一批只做：zimage 样式分离、消息与图片展示抽取、相关测试接入，以及受影响模块的生命周期清理。不同时重写发送流程、生成后端或数据存储。

交付物：模块源码、页面装配调整、直接相关测试、实际验收记录和更新后的 CODEMAP。验收通过后，再确定下一批会话与后端解耦范围。
