# 项目游戏测试：功能开发流程

> 更新：2026-11-02；状态：已接入测试存储、API、工作台、人工证据、独立 Chromium 与有界自动执行；各阶段尚未全部验收，具体见下方实现记录。
> 依据：[测试需求](game-testing-requirements.md)；上位：[阶段 G—N](game-production-development.md)。
> T1—T8 是测试子系统内部顺序，嵌入 G/J/K/L/M/N，不取代原阶段，也不要求先完成存档才能开始核心玩法测试。

## 1. 前置与实施原则

- G 的稳定需求 ID、H 的文件与恢复边界、J 的构建/运行/隔离是基础；K 可后接，手工测试不依赖 Agent。
- 无执行隔离时仅开发用例、结果与报告管理，不开放不受控游戏执行。
- 存档用例依赖 M；依赖未完成如实标记，不阻塞其他无关用例开发。
- 复用已有 owner、项目版本、任务、运行、问题、证据存储与恢复机制，不复制平行服务。
- 只实现一个 Web 适配器，选用现有或已验证的浏览器自动化能力，不先设计全引擎插件平台。
- 首版不包含 CI 集群、真实设备农场、录屏、长期压测或自动视觉审批。
- 依据 ponytail-build、AGENTS.md 与 docs/README.md，隔离测试、避让已有改动、不自动提交重启。

## 2. T1：冻结测试合同与样例

### 早期合同记录（已被当前实现记录补充）

- `core/game_testing_models.py` 复用首期严格模型和 ID/hash 类型，实现独立需求候选映射、计划输入快照、用例版本引用、环境与能力、单用例 attempt、证据索引、报告草稿及执行状态转换校验。
- `tests/test_game_testing_models.py` 验证非法引用、重复 ID、状态转换及结果约束。仅为宿主合同测试，不代表游戏通过测试。
- 现有 Plan 仍为 schemaVersion=1，未迁移；稳定 requirementId 必须由显式采用流程分配并跨修订保留，禁止用文本排序生成身份。候选映射不自动写回项目。
- 当前“快照”仅为完整输入模型，不代表已实现持久化冻结；owner 字段不代替服务端授权。报告校验证据与项目、owner、构建、输入 hash、epoch、运行、会话、用例版本、环境、attempt 及结果来源一致；不证明文件真实存在或内容 hash 正确。
- 报告统计以计划全部用例 × 环境为分母，取显式编号最大的 attempt，保留全部历史；缺项算 not_run，通过/失败混合标 flaky。`requiredCasesPassed` 只表示必需用例统计门槛，不等于交付批准，仍须检查阻断问题、资产/数据、实际证据完整性和未验证设备。
- 当前每条用例适用于全部计划环境；不同环境适用范围需拆计划，不静默跳过。计划最多 100 用例、16 环境；证据单文件上限 10 MiB；报告索引最多各 10000 条 attempt/证据。整体运行容量、超时、事件分页仍待冻结。
- [俯视角样例计划](examples/game-test-plan.json) 包含启动、资源、移动、收集、扣血、胜负、重开七项人工用例。身份、构建、hash、浏览器及平台均是显式占位，未执行；接入真实项目时须替换并重新校验，不能用作通过证据。样例不生成既有项目的需求 ID。
- 上述为早期纯模型阶段，不再描述当前代码状态；当前能力与缺口以文末记录为准。
- 本轮宿主验证：本机 Python 3.13 执行 `python -m pytest tests/test_game_testing_models.py -q`，退出码 0，81 passed。样例通过模型校验后写入；未运行浏览器、具体游戏或付费模型。

对应 G，在写运行代码前完成：

1. 核对实际项目/Plan/Task/Run/Issue 模型，定义需求 ID 和测试引用迁移。
2. 固定 Case、Plan、TestRun、Attempt、Evidence、Report 模型与独立状态机。
3. 定义 buildId、底层 runId、sessionId、testRunId、workspaceEpoch 的关联及所有权。
4. 冻结输入、超时、重试、容量、事件游标、恢复与统计规则。
5. 选定俯视角样例及必需测试：启动、资源、移动、收集、扣血、胜负、重开。
6. 明确首版自动断言可观察的内容；视觉、乐趣与不可观测行为保留人工。

交付：可执行模型、状态转换表、样例计划和接口合同。

检查：合法/非法状态、版本引用、重复 ID、越界参数及无效计划的相关单元测试。

门槛：结果与执行状态分离；blocked/not_run 不算通过；无把文字顺序当稳定需求 ID 的设计。

## 3. T2：用例和人工测试最小闭环

对应 L 的管理部分，可早于 Agent：

1. 用例 CRUD、版本、需求关联、分类和必需标记。
2. 测试计划选择构建、环境和用例版本，开始后冻结。
3. 基础工作台：列表、详情、人工步骤和结果提交，附图片与日志证据。
4. 固定构建的人工运行与独立会话；模型拟定用例只作为候选，不直接算已测。
5. 结果来源与修改历史，证据上传校验格式、大小、权限和文件落盘一致性。

检查：owner、并发、冻结计划、证据归属；界面走通人工失败→创建问题→报告草稿。

门槛：不使用 Agent 也能知道某版本测了什么；无运行证据时不能虚报自动通过。

## 4. T3：Web 试玩驱动与会话清理

对应 J/L：

1. 实现 open/inspect/act/capture/close 和 capabilities，只开放真实支持的动作。
2. 会话绑定项目、版本、调用方和 epoch；输入顺序执行，限制批量数量、时长和日志。
3. 键盘、鼠标、视口变化与截图；触屏不支持则显式拒绝，不退化为鼠标冒充触屏。
4. 取消释放按键/触点，等待在途 open 后清理；只关闭自己的会话和进程。
5. 捕获错误、未处理拒绝与资源失败；校验消息来源及运行令牌。
6. 固定构建执行，开发 HMR 会话单独标观察，不进入正式测试版本。

检查：模拟驱动覆盖取消竞态、跨项目调用、能力缺失、迟到回调和清理重试；真实浏览器验证输入、截图和隔离。

门槛：两个会话互不影响；停止测试不误关人工预览；取消无按键或窗口残留。

## 5. T4：有界执行、证据与断言

对应 L 核心：

1. 按计划执行前置、步骤、等待与预期，执行前校验输入版本和能力。
2. 使用可靠 DOM 或受控只读 bridge 观察状态；Canvas 游戏缺少可验证观察时转人工，不让模型猜通过。
3. 模板测试桥可实现 reset/setSeed/step，测试构建才启用；玩家动作仍走真实输入。
4. 每步关联动作摘要、时间、观察与 evidenceId，失败采集截图与最后有效状态。
5. 区分游戏断言失败与设施故障；取消/中断保留已完成结果，其余按需求标 blocked/not_run。
6. 重跑保存新 attempt，失败不被覆盖；记录不稳定性，不自动反复跑到通过。
7. 服务重启恢复历史记录，无法重新确认的在途任务标 interrupted，不静默续写成功。

检查：启动/资源/主循环样例的真实端到端执行；模拟错误、超时、取消、中断、证据超限和落盘失败。

门槛：截图、断言和构建关系准确；新构建不能继承旧通过；未经实际执行的用例不计通过。

## 6. T5：问题、修复与定向回归

对应 K/L：

1. 从失败用例或人工反馈创建问题，保存复现、期望/实际、版本与证据。
2. 重复问题保留 occurrence，支持人工合并而不丢场景和构建。
3. 关联已有开发任务，修复前快照和基线检查，不另建测试代码写入器。
4. 修复生成新构建，执行失败用例、直接影响项与必要核心冒烟。
5. 修复两轮无效后重新定位，第三轮无新证据不继续；仍失败停止并保留状态。
6. 只有匹配新版本的回归证据才允许关闭，无法复现/暂缓与修复关闭分开。

检查：在隔离样例引入重开未清状态，走完真实失败→问题→补丁→新构建→回归关闭；测试手改冲突时不覆盖。

门槛：代码改变不自动等于修复；失败报告与历史证据仍可追溯。

## 7. T6：设备、视觉、存档与性能增量

对应 L/M，按依赖分别开启：

1. 明确环境 profile：浏览器、平台、视口、DPR、输入能力与真实/模拟标记。
2. 必需桌面视口检查，人工并排截图审批；环境稳定后再加入有掩码与阈值的截图差异。
3. 基线变更有差异与明确采用，失败不能自动替换基线。
4. M 完成后加入存档载入、损坏、版本不兼容和独立测试槽。
5. 按目标需求采集有限性能指标，记录样本、预热与环境；没有可靠指标显示 unsupported。
6. 真实手机、其他浏览器未测即标未验证，不使用缩小视口冒充设备验收。

检查：环境矩阵缺项、基线版本不符、存档污染和损坏恢复；性能采集用固定场景，不对不同机器直接比较。

门槛：每个支持声明都有对应证据；视觉差异不会未经确认自动升级为最终质量结论。

## 8. T7：报告与交付门槛

对应 N：

1. 汇总固定计划、构建、环境、需求覆盖、各结果数量、问题与证据。
2. 必需项失败/阻塞/未测或证据损坏时不允许全面通过；豁免明确为带限制交付。
3. 报告形成后版本化不可静默改写；重测生成新报告，保留历史。
4. JSON/Markdown 导出，校验脱敏与本地相对证据引用，下载检查 owner。
5. Web 包在干净目标环境启动属于独立交付用例，开发预览通过不能替代。

检查：统计分母、缺必需项、过期/损坏证据、未关阻断问题、豁免记录与越权导出。

门槛：交付结论与原始执行一致，无“报告全绿但实际未测”的路径。

## 9. T8：恢复、容量和回归收尾

贯穿 J/M/N，并非最后才考虑恢复：

1. 恢复快照递增 epoch，旧会话停止、迟到事件失效；测试历史保留但当前适用性重算。
2. 按计划、运行、问题建立引用，人工清理前给出影响列表；被引用证据不自动删除。
3. 有界日志、事件分页和证据存储，达到上限标明截断和缺失影响。
4. 模拟应用中断、日志失败、证据部分写入和在途取消，确认不会错误完成或破坏其他项目。
5. 完成测试需求十一项贯穿验收并记录未验证项。

门槛：失败可诊断可恢复；首条链路满足后停止扩展，不追加无关平台。

## 10. 建议接口与模块边界

前缀复用 /api/game-projects/{projectId}，先定位既有服务再确定文件名；不预建空壳 API。

| 资源 | 最小接口行为 |
|---|---|
| test-cases | 创建、读取、修订、归档、需求引用校验 |
| test-plans | 保存、冻结、读取环境矩阵 |
| test-runs | 幂等开始、状态、游标事件、取消、显式新 attempt |
| test-sessions | 打开、观察、动作、截图、归属清理 |
| evidence | 授权读取、元数据、完整性检查 |
| issues | 复用已有问题服务，关联 occurrence 与回归 |
| test-reports | 生成、版本读取、下载 |

操作遵循模型 schema、owner、revision/epoch。数据中只存证据相对引用，二进制不进入项目 JSON；测试 session 与正式预览身份隔离。

## 11. 宿主验证与产品测试的区别

开发测试平台时，用模拟适配器覆盖权限、状态、取消和恢复，验证的是平台协议。用真实浏览器跑样例验证驱动，验证的是运行链路。用户具体游戏仍需自己的用例和证据。

仅执行直接相关宿主测试、项目强制检查与必要真实链路验证；纯文档修改只检查格式与链接。不得为了验证本篇文档运行游戏、安装浏览器或访问付费模型。

记录实际命令、退出码、运行版本、浏览器/设备、通过/失败/跳过；不把看过上游测试用例写成已运行通过。环境不变不重复启动相同阻塞任务。

## 12. 当前实现与检查（2026-11-02）

- `core/game_testing.py`、`routers/game_testing.py`、`static/js/game-test-workbench.js` 已实现需求映射显式采用、用例修订/归档、不可覆盖的计划、人工结果与重测、PNG 附件、证据完整性/授权、问题状态和新构建回归关闭、JSON/Markdown 报告。结果来源明确区分；人工记录不冒充自动执行。
- `core/game_browser_sessions.py` 为可选 Playwright Chromium 驱动：独立上下文、固定产物、禁止外网、真实键鼠、视口、截图、会话归属清理和在途打开取消。未开放 touch/bridge/reset/setSeed/step，不能声明真实手机验证。
- `core/game_test_execution.py` 解释有界动作和 DOM 断言，单环境、最多 10 用例、总执行 180 秒、单用例 30 秒；事件最多 1000 条、分页 100 条。单会话截图最多 10 张/总计 20 MiB，单张 5 MiB。测试索引最多 16 MiB，达到上限拒绝，不自动删除证据。
- 自动执行保存每轮实际 Chromium 版本、视口、DPR；启动错误计入首例，工作区恢复后迟到结果不能通过；取消保留已完成结果，当前用例 blocked，其余 not_run。重启后在途记录标 interrupted，不自动重放。显式自动重测使用同一冻结计划、新运行和新会话，最多三轮；保留旧 attempt，未开始的本轮用例记 not_run，失败/通过混合标 flaky，不自动重试。原报告不可变，重测后可另生成报告。
