## 复现与修复

- 首次真实请求复现候选创建失败：系统提示要求所有测试带 expectedText，与具名端口测试协议冲突。修正系统提示、SDK 示例及校验说明；保持原有校验约束。
- 补充 textField 必须指向已声明文本字段、依赖放 execution.dependencies 等指引，提供可实际执行的图片端口示例。
- 初版节点按固定整除尺寸裁切，101×79 四分后只剩 7800/7979 像素。向真实模型反馈证据，生成 1.0.1：使用 x0=j*w//cols、x1=(j+1)*w//cols，纵向同理。
- 模型修复过程中先后出现 Windows 路径分隔符错误和遗漏 import sys，真实 worker 测试发现后继续修复，最终五项候选测试全部通过。
- canvas_test_plugin 原先将工具调用正常返回误记为 completed，即使报告 status=failed；现根据实际报告显示 failed 并提供原因。
- 模型渠道 HTTP 错误区分 400/401/403/429，不再统一提示“不支持工具调用”；工具异常原因保存并在对话中展示，敏感凭据脱敏。

## 后续：降低模型对协议和收尾流程的负担

用户截图中候选已测试、安装并提交成功，随后模型重复提交工作流，出现数量限制和 Extra data JSON 解析错误。此前只在提示词中要求成功后停止，没有由宿主保证终态，这是流程控制缺陷。现在 canvas_propose_plugin 成功且方案校验通过后直接返回候选，不再请求下一轮模型；多节点工作流应使用 canvas_propose_workflow，不能先提交单插件终态再继续拼装。

媒体命名端口 Python 候选缺失 textField 对应字段时，创建服务自动补齐空文本字段并记录 repairs；不覆盖已有同名字段，不改 worker 代码或测试预期，仍需原有校验、可信代码授权和测试。非法 JSON 返回明确的单对象要求，同一工具连续三次参数解析失败后停止重复调用并保留已有候选；不猜测拼接对象的意图。

验证：候选与 MCP 两套测试 35 passed、18 subtests passed；补充 JSON 循环保护后针对三项相关测试通过。新增覆盖补齐不修改原始输入、不自动授权、已有错误类型仍拒绝，以及真实候选测试后提交即收尾。这次没有再次调用付费模型，没有重建安装包。以上降低协议负担，不等同于通用算法生成能力已解决；模板/确定性算子覆盖、独立行为验收仍需后续完善。

## 老虎机节点失败诊断与协议减负（2026-11-04）

用户截图中 Agnes 多轮创建失败，原因分别是 definition 被编码为字符串、timeoutSeconds=60 超过 30 秒上限、worker 返回的图片协议路径不合规、无 ports 与命名 ports 两种测试格式混用，以及对创建失败后不存在的候选 ID 发起测试。截图不能证明已接通真实人像生成或 UI 动效。

已调整：创建入口仅对单层 JSON 字符串做有界解析，仍经过完整定义校验；不递归解码、不修改代码或测试预期。工具测试 schema 使用互斥约束区分 expectedText 与 expectedPorts，并改善缺失 ports 的诊断。图片路径拒绝策略不放宽，报错与 SDK 明确要求 stdout 使用 images-out/result.png，不用 Windows os.path.join 拼协议路径。修正系统提示词中“图片 worker 一律 v2”的冲突，重申有 ports 使用 v3；创建失败不能猜候选 ID。

能力边界已同步给模型：当前自定义 UI 是白名单表单、CSS 与隔离 Worker；不支持 SVG、Canvas、img、网络或 DOM 脚本。data-action 仅通知 UI Worker，不能启动 ComfyUI；现有 Comfy 独立节点仍使用原生参数 UI。不得把 Pillow 示意图或随机提示词当作真实人像生成，也不得声称一体化老虎机节点已经交付。此前面向用户的通用 HTML/CSS/JS 能力描述过宽，现予以纠正。

验证：候选与 MCP 两套测试初跑 45 passed、18 subtests，新增测试仅一项对 Pydantic 默认字段展开的断言不当，改为比较规范化定义后，两项新增测试均通过；代码检查通过。没有调用付费模型，未完成老虎机实机生成验收，未重建安装包。后续真正的一体化交付需要受控 UI 动作执行桥接、状态/结果回传和真实图像生成验收，不能靠放宽 worker 权限替代。

## 后续：受控自定义 UI 执行桥接（2026-11-04）

Comfy 构建候选新增可选 ui，复用 NodeUI 白名单、脚本大小和字段绑定验证。ui 随测试版本保存并发布到独立节点定义，AI 可通过 comfy_create_build 一次提交工作流、参数映射与交互 UI。扩展节点和封装 Comfy 节点共用 CanvasPluginUI 执行桥，原生执行入口保留。

isolated.form 的 data-action="run" 可直接执行；isolated.worker 在真实用户点击 action 后 5 秒内可返回一次 {type:"execute",params:{字段ID:值}}。宿主验证 frame/session、字段集合、类型和范围，运行前同步参数，只执行该节点既有执行器；init/state/合成点击不获得执行窗口。运行锁跨视图重建保留，禁止并发重复请求。UI 没有网络、宿主 DOM 或原生调用权限，SVG/Canvas/任意 img 仍不在白名单。

Worker 收取 state：status 为 idle/running/succeeded/failed，附带 error/text/images 只读引用；需在 2 秒内响应。宿主显示状态和可信图片预览。由于隔离 iframe 不携带正常页面认证，预览由宿主读取同源 /output/ 图片，限定 PNG/JPEG/WebP，最多 8 张、总计 8 MiB，单资源读取限时 10 秒，再以数据 URL 回传。大图可在原输出节点查看。动画临时状态不保证刷新恢复，参数和执行结果沿用画布保存机制；没有增加跨重启执行恢复或任务取消协议。

Comfy 封装节点修复原有两秒后自动清除 running 的行为，改为实际结束才释放，避免 UI 重复提交；原有通用 Comfy 节点行为保持。AI 提示和 SDK 已更新，新增可直接复制的 uiExecuteExample。
