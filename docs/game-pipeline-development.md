# 策划到美术：开发流程

> 更新：2026-11-02；状态：首期核心 API 与画布接入已实现，真实生成和完整浏览器验收待完成。需求依据：[首期需求](game-pipeline-canvas.md)。
> 已接入项目面板、业务路由与现有 API 图片生成器；代码完成不等于真实渠道验收通过。按阶段门槛推进，不承诺未经评估的工期。

## 1. 开发约束

- 默认入口为“一句话灵感 → AI 完整游戏方案”，可留空让 AI 自由构思；复用已配置的 LLM，渠道与模型放入可选高级设置。详细策划表默认收起，生成后展示可读方案，由用户采用；不得要求先手填完整策划才能生成。文档导入仍为可选来源。
- 主入口改为画布列表的“游戏项目”类型（kind=game），自动初始化项目和三个阶段节点。static/js/game-workflow.js 复用项目 API，节点连线参与输入校验，上游灵感改变后阻止沿用旧策划拆解；需求正文直接在文档节点编辑。项目面板保留验收和导出；旧版项目首次打开时补充阶段节点。
- 策划与资产拆解节点仅显示一个“聊天模型”下拉菜单，从 `/api/providers` 的公开配置中列出已启用且已配置密钥的模型，选项携带对应渠道并随节点保存；不在节点填写接口、渠道或密钥。不使用 `/api/config` 的原始渠道列表推断 has_key，也不默认回退到未配置的渠道。
- 模型旁可选择角色预设：策划提供游戏制作人、玩法系统策划；资产拆解提供游戏美术总监、角色设定师、2D 素材规划师，另有通用助手。选择随节点保存并实际进入系统提示词；候选记录 ID 与版本，不绕过契约校验。参考来源与改编范围见 [角色预设说明](ohmygame-role-presets.md)。
- 模型返回纯 JSON 或完整 Markdown JSON 代码块都可解析；原始响应留存不变，剥离外层标记后仍执行同一套完整契约校验。截断内容、附加说明文字与无效资产字段不放宽校验；概念图也必须有 references/ 下的有效目标路径。
- 资产候选兼容遗漏外层方括号的完整逗号分隔对象序列；系统绑定、选用和验收字段不进入模型 schema 与上下文，模型擅自返回这些字段时丢弃并由系统维护。先检查路径安全，再按 concept/runtime 修正误用的 assets/ 与 references/ 前缀；不修补截断 JSON、危险路径或不支持的素材类型。节点失败提示包含本次具体诊断，原始候选保留。

- 复用现有 FastAPI、原生前端、身份校验、画布、LLM 配置和图片生成器，不重写框架。
- 不先迁移画布存储，不先做 Agent 平台；先贯通一个图片通道再扩展。
- 按 ponytail-build 先查现有实现，再使用现有依赖与平台能力，最后写必要代码。
- 以实际 HTML 脚本引用为准。frontend-modules.md 已标为待验证，不依赖其中声称完成的统一引擎或 manifest。
- 遵循 docs/README.md：隔离测试、模拟上游、不自动提交、不自动重启、不操作真实用户资产。
- 当前工作区有无关未提交修改，开始每阶段前记录并避让，不覆盖或回滚。

## 2. 已确认的复用位置

| 位置 | 可复用能力 | 开发前需补查 |
|---|---|---|

## 3. 阶段 A：冻结契约与接入点

工作：

1. 局部追踪画布创建/保存、LLM 请求、生成启动至结果回写。
2. 固定项目、文档、策划、资产、选用文件和 revision 的模型、上限与权限。
3. 明确项目与画布的权威数据来源、文档恢复及双文件绑定恢复方式。
4. 选定一个实际可用的图片渠道，记录其尺寸、透明和参考图能力。
5. 建立五项资产的贯穿样例，核对建议接口与现有路由冲突。

交付：可执行校验模型、接口合同、接入点清单、样例数据。

门槛：image 不被当生成器；无未定义数据源；不依赖未经确认的框架或任务平台。

### A 的实现记录（2026-11-02）

- 可执行契约：`core/game_project_models.py`；五项样例：`docs/examples/game-project.json`。拒绝未知字段，限制 ID、长度、数量、规格，检查引用、循环、路径、绑定唯一性及正文 UTF-8 字节数/hash。owner 必须由后端身份产生，模型校验不代替权限检查。
- 正文上限固定为 1 MiB（1,048,576 字节）；项目最多 100 文档、200 资产，图片每边最多 8192 像素。规格上限是存储校验边界，不代表上游支持全部尺寸。
- 共享风格引用适用于未设 visualOverride 的资产；共享参考本身不产生隐式自引用。单项覆盖完全替代共享风格；显式 referenceAssetIds 仍生效。
- 实际页面 `static/canvas.html` 引用 `static/js/canvas.js`。复用 addPromptNode、addGeneratorNode/addMsGenNode、runGenerator 和 addGeneratedImageNode；CANVAS_GENERATOR_TYPES 中包含视频类型，项目图片生成不得直接照单开放。
- 画布 PUT 仅保存既有 CanvasSaveRequest 字段；项目元数据必须走独立接口。项目关联只以 project.json 的 canvasId 为准，不写画布反向字段，避免双文件关联事务；创建项目在跨进程锁内检查唯一关联。画布保存会校验文档引用，不能用普通 PUT 写入跨项目文档节点。
- LLM 应复用 resolve_chat_provider 和 httpx 请求方式，不能直接转发 `/api/canvas-llm`：该接口没有返回 finish_reason，且将空文本替换为提示文字。阶段 C 必须检查原始上游结束原因和空输出；文档作为 user 内容，不拼入 system 指令。
- 当前实际接入 generator → `/api/canvas-image-tasks`，沿用配置中的 API 图片渠道与模型、并发和任务恢复。尺寸由资产规格传入，实际能力仍取决于所选模型；已选参考图通过授权的不可变项目文件地址进入现有本地图片解析器。原 msgen 下载失败时可能返回远程 URL，尚未开放为项目绑定渠道；选用接口只接受已落地且当前账号可访问的图片。
- 策划/清单候选使用等待响应模式，上游错误和截断不覆盖正式版本；结构错误最多修正一次，保存两次原始输出及诊断。断开后不自动重试付费请求，服务端已完成的候选可重新读取。现有图片任务为进程内状态，服务重启后的未知上游结果不自动重跑。未调用真实渠道，因此“实际可用渠道”验收仍未通过。
- 新路由前缀 `/api/game-projects` 已注册，继承账号身份和画布访客开关；隔离测试覆盖真实 main 导入、路由注册和 HTTP 请求，并与 Git HEAD 比较原有 main 路由及 include_router 合同。

候选、来源快照、参数快照和 revision 模型见 core/game_project_models.py；逐接口请求模型见 routers/game_projects.py，FastAPI OpenAPI 为可执行接口合同。项目归档解除活动关联，保留文件；正文以索引中的上次保存内容为权威，落盘中断通过 GET recovery 明确报告并由用户恢复。未引用的版本文件不自动清理。

系统默认 Python 3.12 缺 pydantic，本次使用已有 Python 3.13，未修改全局环境。已为本需求的两份文档和单个样例增加精确 Git 忽略例外，不放行其他 docs 内容。最新验证与限制见第 12 节。

## 4. 阶段 B：项目与文档

工作：

1. 项目创建、读取、画布关联、归档与解除关联；失败后能恢复。
2. 项目独立目录保存，不迁移原画布格式。
3. 文档 CRUD、Markdown/TXT 导入、节点摘要和正文编辑。
4. revision 冲突检测、owner 校验、正文与索引不一致恢复。
5. 实际接入节点创建、保存、重开、删除和复制语义。

检查：相关后端测试覆盖权限、并发、路径和正文恢复；界面验证创建、导入、保存与重开。

门槛：不用 AI 也能管理策划文档，普通画布仍可使用。

## 5. 阶段 C：策划生成与采用

工作：

1. 接入现有 LLM 配置，输出结构化策划候选并服务端校验。
2. 显示待确认问题和假设，允许编辑、采用、丢弃；采用才修改正式版本。
3. 候选绑定来源 hash/revision，生成中来源改变时提示冲突。
4. 区分生成状态、结构有效与用户确认；截断和失败保留旧版。
5. 校验错误最多修正一次，保存原始候选与诊断便于处理。

检查：直接相关测试覆盖合法输出、结构错误、空结果、截断、来源变化、旧版保护；界面走通采用流程。

门槛：得到可修改、可确认的策划，失败可恢复；没有自动发起美术生成。

## 6. 阶段 D：资产清单与节点绑定

工作：

1. 策划拆解清单候选、手工编辑、稳定 ID、差异采用。
2. 规格、用途、必需标记、概念/运行时分类、共享风格与参考管理。
3. 后端校验唯一 ID、引用、循环、路径、规格和未知字段。
4. 只遍历 assets 创建现有提示词与生成器，按项目和资产 ID 幂等绑定。
5. 处理创建中断、重复点击、删除恢复、撤销和复制；复制生成节点不自动抢占原绑定。
6. 删除与移除资源不自动清理文件，受引用时明确提示。

检查：校验、幂等和中断恢复测试；界面确认五项对应五个绑定，重复创建不增长。

门槛：绑定稳定可恢复，节点创建与付费生成分离，现有生成器独立用法保持兼容。

## 7. 阶段 E：真实生成、选用与更新

工作：

1. 先完成一项资产：节点生成 → 候选归属 → 显式选择 → 文件复制落地。
2. 保存实际参数、参考与资产 revision；重复回调不重复登记，旧结果不覆盖新选择。
3. 检查真实格式、尺寸、alpha 信息并记录人工质量确认。
4. 加入选中资产批量执行，沿用现有并发/取消边界，单项失败可重试。
5. 规格、提示词和共享风格变化时局部标记待更新；旧选用文件继续保留。
6. 实现上传修正版或复用已有处理入口，不额外承诺自动后处理能力。

检查：候选归属、晚到结果、选用文件保护、复制中断、缺失文件、规格检查与局部更新。

真实验收：有用户触发或明确生成授权时运行实际渠道，验证参考图和选用链路；没有执行时记录“真实生成未验证”，不以模拟结果冒充。

门槛：五项资产可各自选用；项目管理真实文件；失败和重开不丢失选择。

## 8. 阶段 F：导出与首期交付

工作：

1. 生成版本确定的 manifest、策划快照、检查摘要与 ZIP。
2. 必需项未完成时阻止正式完成，允许显式草稿导出。
3. 检查路径冲突与逃逸，概念图放 references；导出不泄漏内部路径或凭据。
4. 下载检查 owner，记录导出对应项目 revision。
5. 在隔离样例完成需求文档九项验收，记录通过、失败和未验证项。

检查：实际解包，核对清单路径和 hash；覆盖缺必需项、越权下载与草稿包。

门槛：首期可完成策划到资产交付；不宣称已经具备代码、试玩或游戏发布能力。

## 9. 建议接口合同

以下为候选路由，不是已实现 API；阶段 A 核对前缀、注册顺序和请求模型。写入携带 baseRevision，冲突返回 409。

| 方法与路径 | 职责 |
|---|---|
| POST /api/game-projects | 创建并关联画布 |
| GET /api/game-projects/{id} | 读取项目与版本 |
| POST /api/game-projects/{id}/archive | 归档并解除关联 |
| POST /api/game-projects/{id}/documents | 创建或导入正文 |
| PUT /api/game-projects/{id}/documents/{docId} | 保存正文 |
| DELETE /api/game-projects/{id}/documents/{docId} | 检查引用后移除，保留文件 |
| POST /api/game-projects/{id}/plan-candidates | 生成策划候选 |
| PUT /api/game-projects/{id}/plan | 保存编辑或采用策划，明确确认状态 |
| POST /api/game-projects/{id}/asset-candidates | 生成清单差异候选 |
| PUT /api/game-projects/{id}/assets | 保存清单、风格及采用差异 |
| POST /api/game-projects/{id}/assets/{assetId}/binding | 保存并核对生成节点绑定 |
| POST /api/game-projects/{id}/assets/{assetId}/selection | 校验候选、复制选用文件 |
| POST /api/game-projects/{id}/assets/{assetId}/review | 规格检查及人工确认 |
| POST /api/game-projects/{id}/exports | 创建正式或草稿包 |
| GET /api/game-projects/{id}/exports/{exportId} | 授权下载 |

实际生成复用既有端点，不复制七套生成 API。长耗时候选的响应、断开和恢复在阶段 A 按现有能力确定，不假定已有后台任务系统。

## 10. 验证与停止条件

- 每阶段只跑直接相关测试与项目强制检查，不为局部改动跑全量套件。
- 路由变动检查隔离应用导入和真实路由注册；语法检查不能代替接口验证。
- 节点交互变动按影响验证创建、保存、重开及删除/撤销，不机械全站回归。
- 记录实际命令、退出码、跳过原因；无变化不重复检查。
- 前一阶段门槛未满足不扩大范围掩盖问题；无关历史失败只记录。
- 交付时明确已实现与未验证能力，不自动清理资源、提交或重启服务。

## 12. 当前实现与验收记录（2026-11-02）

### 已接入

- 画布工具栏“游戏项目”入口，文档、策划、资产清单、生成与交付四步面板；沿用现有主题，不重写页面框架。
- 项目创建/读取/按画布查询/归档解除活动关联；不迁移旧画布。项目级 revision 和跨进程文件锁保护并发及关联唯一性。
- 文档新增、编辑、UTF-8 Markdown/TXT 导入、删除引用检查、正文中断恢复；文档节点显示摘要与版本，但只落盘项目/文档定位信息，复制保留同项目正文引用，跨项目在前后端均拒绝。
- 策划/资产候选生成、原始输出与诊断、一次结构修正、编辑/采用/丢弃、来源变化显式确认；正式版本不会被截断/空响应/失败覆盖。
- 手工编辑资产、清单新增/修改/移除差异、风格覆盖和参考；按资产清单创建提示词/API 图片生成器并校验绑定，复制生成节点不继承绑定。中断可从已保存节点标记恢复，不自动生成。
- 候选归属、提交时实际参数与修订快照、回调去重、绑定历史、选用文件原子复制、上传修正版、真实图片格式/尺寸/alpha 检查和人工确认。
- 修复共用图片任务入口只解析 URL token 的既有问题：现在 Cookie/Header/URL 身份统一经过 require_valid_token，生成结果写入正确用户目录；任务读取检查 owner，拒绝匿名提交与越权读取。不改变既有任务 API 路径。
- 选用图片采用不可变的项目版本文件，参考图读取校验 owner；原始生成文件缺失不影响已复制文件。修改规格/提示词/参考/共享风格或换参考图时，只标记受影响项及其依赖，保留旧选用文件。
- 批量生成先显示数量与渠道，无报价不虚构费用；按既有图片任务串行提交，单项失败独立处理，停止只阻止后续提交，不冒充上游取消。
- 正式/草稿 ZIP、manifest、策划快照与含人工确认的检查摘要；正式导出检查必需资源、待更新、规格、hash 和确认状态。导出锁定项目 revision，下载校验 owner。
- 本机当前已有服务未自动重启，也未调用真实付费生成接口；应用此后端改动需要按现有启动方式重启服务，再刷新画布页面。

### 实际检查

执行环境：现有 Python 3.13、Node；所有后端测试使用临时目录和模拟上游。
